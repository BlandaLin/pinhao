# 拼好汉化工作台桌面版

Electron + React 桌面程序，连接实际项目库、原生适配器、模型 API 和文字工作包。
首发平台为 Windows 10/11 x64，可处理受支持的 32 位游戏。

## 使用发行目录

```text
local/releases/<版本>/PinhaoWorkbench-win32-x64/PinhaoWorkbench.exe
```

保留整个目录，双击 `PinhaoWorkbench.exe`。固定 Python、原生编解码工具和霞鹜文楷随发行目录
提供。便携版设置、加密后的 API 配置与轻量项目索引保存在程序旁的 `data`；
随游戏增长的文字、技术产物和恢复记录保存在游戏旁的“游戏名-拼好工程”，
独立成品另放“游戏名-汉化版”。不要将自己的 `data` 或工程目录一起分享。
布局与写入权限说明见[项目存储](../../docs/product/PROJECT_STORAGE.md)。
桌面与开发宿主同时使用程序默认及 Windows 已信任的根证书，兼容系统证书环境，保持 HTTPS 与域名校验。

1. 在“设置”填入技术连接与文字连接的 API 地址、模型和密钥；两类连接可使用相同模型，翻译与校对共用文字连接。
2. 添加游戏目录，工作台建立项目并完成提取与原样回写检查。
3. 点击开始，执行技术检查、场景小样、翻译和校对；也可以导出工作包给外部 AI 或人工。
   技术 Agent 需要运行新脚本时，在制作总览的“技术脚本执行”中为当前项目授权。
   脚本以当前 Windows 用户权限运行，可以访问该用户的文件及网络；产品不向脚本传入 API 密钥。暂停后可撤销授权。
4. 在文字工作台审阅、搜索和修订；外部回包导入时自动检查基线与冲突。
5. 生成独立游戏，从成品页启动测试、打开目录或导出分享 ZIP。
6. 游戏更新后，在项目总览选择“接入新版”，建立新项目并复用源文与上下文一致的已接受译文。

MV/MZ 成品提供“导出手机游玩包”，生成 JoiPlay 标准 `.rga`。在手机上使用 JoiPlay 导入，
中文资源与字体随包保留，桌面运行器和私人存档在导出时排除。包内附桌面插件引用检查与试玩项目，
手机端启动、触控、音频及存读档由实际设备验收。格式与范围见
[游戏类型与手机游玩](../../docs/product/GAME_TYPES_AND_MOBILE.md)。

制作总览提供“仅翻译”“仅校对”“定向补漏”，也可以继续使用一键制作。
导入过程中可以取消；项目总览提供删除入口，可选择保留文件或清理工作缓存，原版、成品和存档保留。
本地 Qwen 等模型可通过兼容接口接入，地址、角色搭配与实测范围见
[本地模型接入](../../docs/product/LOCAL_MODELS.md)。

默认并发为 3，局部失败经有限重试后保留原文并继续；设置可改为遇到局部失败暂停。接口持续
失败、核心文字任务整体失败和构建失败会暂停对应阶段，已接受成果保持可恢复。

设置内置思源宋体 2.003、思源黑体 2.005、霞鹜文楷 1.522，默认选择霞鹜文楷。字体卡片使用
对应的本地字体显示示例，点击即可选择；也可沿用游戏字体或选择自己的 TTF/OTF。
三款字体固定常规字重、官方版本与 SHA-256，采用 SIL Open Font License 1.1，独立成品附带
所选内置字体的许可证。MV/MZ 与 RGSS 路线安装字体及默认姓名显示
兼容模块；WOLF 由原生工具配置字体。2000/2003 成品携带 EasyRPG 与中文字体，使用
`PinhaoStart.cmd` 独立启动；特殊运行器插件按游戏验收。

图片处理在设置中开启，视觉模型识别界面候选，文字进入同一翻译校对队列；平整背景 PNG
可以回写，复杂背景、JPEG 与识别失败区域保留原图并记录。各项能力和真实检查范围以
[实现矩阵](../../docs/product/IMPLEMENTATION.md) 及项目的成品检查记录为准。

## 游玩辅助

从成品页启动 MV、MZ、XP、VX、VX Ace 游戏，进入新游戏或读取存档后连接辅助。

- **角色与物品**：搜索并调整金钱、物品、装备、开关、变量、等级、经验和 HP/MP，或恢复全队。
- **移动与探索**：穿墙、原生移动速度、随机遇敌开关、相对跳跃、地图搜索与坐标传送；支持恢复移动设置。
- **回想与图鉴**：本地扫描事件与插件的解锁条件，按条目查看依据并应用；需要进一步判断的候选可交给技术 Agent 分析。

扫描可在游戏关闭时运行；默认使用本地工具，点击技术分析才调用设置中的技术模型。
当前回想路线覆盖明确事件条件与已识别的 RecollectionMode 配置，其余候选列入待核对记录。
RecollectionMode 使用画廊显示层；事件配方只提交已确认的相关状态。每次应用前保存原值，
备份绑定成品版本和当前读取的游戏会话；在同一次会话中恢复。恢复时保留随后发生变化的状态，
变量阈值也会保留已达到的进度。辅助修改由游戏内存档保存，随机遇敌开关控制原生随机战斗。

Ren'Py 成品提供“命名变量”：按 `store`、命名 store 与 `persistent` 搜索已有游戏变量，
按原有布尔、数字、文字类型编辑。store 修改随游戏内正常存档保存，persistent 修改即时保存到
该游戏的持久数据；读档和回退刷新辅助会话。公开模板与官方 7／8 代运行器分别验证。

2000/2003 与 WOLF 使用“存档编辑”，关闭游戏后选择存档，按名称搜索并修改；每次写入保存
原文件备份。TyranoScript、KAG3、Godot 2/3/4、PGMM、Unity Mono、SGB 与 Bakin 提供
实时变量与状态编辑。界面按实际资源显示入口，详情见[游玩辅助说明](../../docs/product/PLAY_ASSIST.md)。

## 从源码运行

在仓库根目录使用 Node.js 24.5+ 和 npm：

```powershell
npm ci
npm run prepare:tools
npm run prepare:dsh -- --build
npm run build
npm test
npm run test:engines
npm run test:ui
npm run desktop
```

`prepare:tools` 准备固定 Python、三款内置字体及其许可证、原生引擎工具。首次准备需要网络；开发测试和
构建复用本机缓存。DSH 固定依赖和构建条件见[技术运行时](../../docs/product/DSH_RUNTIME.md)。
`test:engines` 需要可用的 Python，固定发行运行时为 3.12.10。
Windows 源码构建通过系统 .NET Framework 4 编译器生成托管运行桥，旧版目标引用 .NET 2.0
程序集；构建机需启用 Windows 的“.NET Framework 3.5”功能。发行目录携带编译好的桥文件。

`test:ui` 使用隔离、隐藏的 Electron 窗口和中性内存后端，验证编辑器保存与重载期间的继续
输入及条目切换。测试调用的模型端点、存档和游戏资源均使用本地中性样例；正常测试流程
无需真实 API 密钥。

```powershell
npm run package
```

打包命令构建界面并生成 `local/releases` 下的 Windows x64 便携目录。发行目录包含依赖
许可证；根 `local` 的项目、研究资料与个人配置留在开发机。

`npm run dev` 提供连到同一核心服务的本机开发界面。完整 Windows 密钥存储、原生文件对话框、
游戏启动与游玩辅助通过 `npm run desktop` 验证。开发宿主与正式 Electron 密钥存储区分开。

## 代码入口

| 路径 | 职责 |
| --- | --- |
| `electron/main.mjs` | Electron 窗口、系统加密、IPC 与原生对话框 |
| `electron/host.mjs` | Python 协议宿主、字体准备、成品启动 |
| `electron/preload.mjs` | 类型化业务接口的最小桥接 |
| `src/App.tsx` | 项目导航、制作状态和成品入口 |
| `src/Workbench.tsx` | 搜索、分页、当前译文编辑与版本提交 |
| `src/Settings.tsx` | API、角色模型、并发与处理选项 |
| `src/Assist.tsx` | 引擎能力对应的实时连接与存档编辑 |

本目录是正式产品代码入口，核心命令由
`packages/contracts` 定义，业务实现集中在 `packages/core`。
