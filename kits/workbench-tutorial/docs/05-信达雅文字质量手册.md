# 信达雅：文字 AI 的质量底线

适用对象：只负责翻译、校对、润色的 AI 或文字人员。先读本轮任务卡；本手册解释如何判断文字，不改变工作台接口。不会编码也可以完成这些工作。

## 1. 先保住原意，再谈文采

| 层级 | 本轮目标 | 怎么验收 |
| --- | --- | --- |
| L1 信与达 | 不漏关键信息、不添设定；人物关系、主客体、否定、数量、条件与术语正确；中文能读懂 | 对照原文、上下文和术语表；结构另外由程序校验 |
| L2 自然与一致 | 中文句法自然；称呼、视角、角色语气连贯；菜单、物品和叙述各有合适文体 | 连读完整场景；检查同一角色及同类界面文字 |
| L3 风格与节奏 | 保留有意义的停顿、断音、拖音、敬语差异、拟声质感和情绪变化 | 对照原文的作用，而不是规定每种声音只能用某个汉字 |

优先级是 L1 → L2 → L3，不用华丽措辞掩盖没看懂的句子。风格本身承载情节、语气或人物身份时，它也是必须保住的原意，不能以“L3 可选”为理由抹掉。

**结构正确不代表 L1 合格。** 没丢 ID、占位符和记录，只能说明回包可继续处理；“她/他”写反、否定变肯定等仍可能全部通过程序。

## 2. 拿不准，留证据，不编得顺

有证据才能改。性别、称呼、动作发出者、承受者、物品所属人都以原文及上下文为依据，不凭职业、外貌或姓名猜。

原文省略主语，中文能自然省略时也省略。必须说明对象而证据不足时，不强行选“他/她”。专名尚未批准，不自行造中文译名；暂留完整原名或当前版本，记录待定项。

看不懂的习语不强迫字面翻译：错误直译也可能编造另一层含义。保留当前值，明确标记未解决。第一次翻译还没有译文时保留原文，不能用空串、删记录或“已完成”掩盖。

备注写在既有 `notes` 或 `NOTE=` 中，每项说明疑点和需要的证据。例如：

```text
[待确认:人称] 原文省略主语，当前“她”无证据；需前后对话与角色资料。
[待确认:专名] 无批准译名，暂留原名；需术语负责人确认。
[待确认:语义] 两种理解会改变动作对象；需上一消息窗。
[技术约束] 保持原意后可能超出姓名框；请技术侧检查显示。
```

这些是备注约定，不是新增 editable 字段。不要把备注塞进译文正文。待确认项在报告中保持未解决状态；记录了疑点不等于已经修好。

## 3. 术语先定，例外有据

开始一批前阅读已批准术语、角色资料与当前版本。术语表至少说明原文、批准译名、适用范围、允许别称以及证据；未确认的部分明确留空，不把建议当定稿。

优先检查完整复合词，再看其中的短词。角色称呼可能随身份、关系和场景变化，不能只靠原文子串命中决定对错。动态姓名占位符保持动态，不替换成固定名字。

同一原文在不同语境中可能有不同译文：按钮的 `Back` 是“返回”，叙述里的 `back` 可能是“背部”。反过来，相同用途的固定系统词应一致。重复项只产生核查候选；只有上下文、用途和约束都确认相同，才共享译法。

发现术语冲突，文字 AI 提建议，负责人确认新版本后再统一；不要私改术语表使自己的回包显得合规。

## 4. 按文字用途做处理

| 类型 | 重点 | 不该做的事 |
| --- | --- | --- |
| 系统、菜单、战斗提示 | 含义准确、简短、同类一致、格式符不变 | 为好看删数量、条件或变量 |
| 选项 | 保留选择的后果、否定与人物态度 | 把不同分支改得含糊或完全相同 |
| 物品与说明 | 谁的物品、功能、使用条件、数值准确 | 只根据物品名补不存在的功能 |
| 对话、叙述 | 连读消息窗，核对说话人、视角和前后关系 | 为单行流畅接上另一条互斥分支 |
| 拟声、短感叹 | 声源、动作、强度、持续时间与节奏 | 一律变成“啊……”或随意放大强度 |
| 图中文字、脚本 UI、旧存档字符串 | 记录位置，另交技术侧判断 | 以 editable 已完成推断它们也已完成 |

文本框太窄不等于可以删意思。先给出忠实自然译文并标注显示风险，由技术侧测量字体、换行和框宽；确需缩写再由文字负责人审核。

## 5. 拟声与语气：翻作用，不套字典

先判断是什么在发声、动作幅度与持续时间，再选中文写法。`グツグツ` 在沸水场景通常表现沸腾；`ドクドク` 在心跳场景通常表现搏动。脱离场景，不规定所有出现位置都必须用同一个中文拟声。

促音可能表现截断、急促或强调；长音可能表现拖腔；浊音记号可能表现粗哑。按上下文重现它们的作用，不机械规定促音必须变顿号、长音必须变波浪号，也不全局删除中文引号。

`♡`、`♥`、`♪` 的处理由项目约定决定。若项目要求逐个保留，就不擅自压缩重复；若允许字体或标点替代，应先批准并记录。标点的数量不是跨项目通用的语义验收标准。

内容语气既不自行淡化，也不自行加重；不加原文没有的动作、情绪或设定。遇到无法承担或无法判断的内容，如实交回未完成范围，不伪称译完。

## 6. 润色只修有问题的地方

先列出误译、关系错误和不通顺处；然后改善中文表达；最后处理有证据的风格损失。已准确自然的文字保留，不为增加改动条数重写整批。

“进行了”“无法直视”等不是一出现就错。检查句子是否拖沓、含义是否匹配，再决定修改；自动替换可能把羞怯改成厌恶，把持续动作改成瞬间动作。

朗读能帮助发现不自然的中文，但不能验证原意。只看中文的读者可以反馈可读性，语义验收仍需对照原文。对照同一角色的几段对话，可检查口吻是否被磨成同一个声音。

## 7. 交付的最小闭环

1. 读取当前有效版本、术语表、只读上下文和本轮任务卡。
2. 只改被允许的译文及备注；保留完整 ID、顺序、数量和占位符。
3. 有证据的错误直接改；其余疑点逐 ID 留备注。
4. 返回完整约定文件，列出实际核查范围、修正项、存疑项和未检查范围。
5. 技术侧校验结构，文字负责人审定语义，再将当前完整有效版本交给下一阶段。
