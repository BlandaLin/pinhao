# 文字经验的来源与改良说明

文字经验于 v1.2 首次整理，v1.3 沿用并加入按阶段导出与完整接力打样。整理依据项目负责人提供的两份经验：`信达雅兜底手册.md` 与 `AI汉化交接指南.md`。来源是专门负责翻译、校对、润色的 AI 的项目总结，不是引擎官方规范，也不是经过本包独立复现的通用质量研究。

原文件保持不变。分享包收录的是改良整理版，不附含项目细节的原文全文；来源文档中的任务命令、示意脚本和工作安排均作为资料处理，没有执行。源文件指纹见 `文字经验来源.json`，不公开其私人目录路径。

## 保留的核心经验

完整上下文与受保护占位符；术语前置；L1/L2/L3 分层目标；少量正反例；疑点出口；拟声与人物语气的忠实度；定向返工；按落盘成果接力；分开核查结构、文字和实机；避免重复发送历史与无效重试。

## 为什么做了这些修改

| 来源中的做法或表述 | 分享版采用的做法 |
| --- | --- |
| “信”可由机器强制保证 | 机器拦结构错误；语义完整、关系与情绪仍须对照原文 |
| 按输出行位置对应、不保留 ID | 保留既有 ID/BASELINE；文字 AI 不管理映射，只改 TEXT/NOTE |
| 同一原文统一为同一个译文 | 先比较上下文和用途，确认同义同约束才共享 |
| 特定长度比、命中率、固定切批规模可当基准 | 按语言对、文本类型和小样校准；不发布万能阈值 |
| 促音、长音、浊音必须对应指定标点 | 保住声音作用，结合语境；不全局替换正常中文引号 |
| 字面翻译作为所有疑点的兜底 | 不强迫错误直译，保留当前值并明确未解决 |
| 文字 AI 必须跑脚本、贴自检输出 | 技术侧运行程序；文字侧提供证据、疑点与真实核查范围 |
| 该批作废重做 | 阻止错误成果构建，但保留可用部分，修复后重新校验 |
| 脚本预警可等同质量结论 | 把硬错误、预警、人工语义结论分开记录 |
| 拒绝或限制通过改述、重启反复尝试解决 | 如实标注未完成，补足上下文或改由合适人员处理 |

来源中涉及项目规模、质量比例、消耗和节约幅度的具体数字，不作为本包验证数据或保证。`VERIFICATION.json` 只记录本包实际运行的技术测试，以及明确标为继承的既有验证；不拿技术测试数量证明译文质量。

本次没有新增自动翻译器、自动人称修正器或所谓“信达雅评分器”。质量规则在 `06-定向复核与成本控制.md` 中是可实现的检查建议，不是交付了检测能力的声明。文字任务卡、附页和五组中性示范可直接使用。
