# 已有工作包直接转成纯文字填写包

使用本教程附带 toolkit 生成的有效 work，可直接导出纯文字任务包，文字 AI 不需要理解 JSON 字段或计算 hash。下面命令由技术 AI 执行，不需要交给文字 AI。

## 初翻

```powershell
python lesson.py export-text --stage translation --work '<现有work目录>' --out '<新的文字任务目录>' --glossary '<已定稿术语表.json>'
```

目录内有 TASK.md、READING.md、glossary.json、return-text.txt。只交这一小包给文字 AI，它只改 TEXT 与 NOTE，不改文件头、ID、顺序与控制符。没有 glossary 参数也能导出，但只产生待负责人填写的空术语表，不自动猜人物资料。

另有技术侧 `export-report.json`，记录阶段、数量和当前工作表指纹；文字 AI 不需要编辑它。省略 `--stage` 时默认初翻，兼容旧命令。READING 同时带原文、当前译文和只读上下文。

## 接回

```powershell
python lesson.py import-text --work '<同一个work目录>' --text '<返回的return-text.txt>' --out '<新的接回目录>'
python toolkit/kickstart.py build --work '<同一个work目录>' --editable '<新的接回目录>/editable' --out '<新的构建目录>'
python toolkit/kickstart.py verify --work '<同一个work目录>' --editable '<新的接回目录>/editable' --build '<新的构建目录>'
```

转换时先核对固定基线、完整 ID 集合与顺序，再还原原工作表字段、校验占位符与引擎目标规则。notes 留在 editable 供审阅，build 不写进游戏；如需单独 notes 文件，教学 integrate 会生成，真实项目技术侧可另导出。

失败不会生成成功报告，可能留下用于检查的部分输出，重试用新目录。不要把失败表直接拿去打包。构建仍只输出数据集合，按对应引擎导入测试副本；语义、字体和实机仍需检查。

## 校对与润色接力

用上一阶段完整有效 editable 明确作为输入：

```powershell
python lesson.py export-text --stage proofreading --work '<同一个work目录>' --editable '<初翻接回目录>/editable' --out '<新的校对任务目录>' --glossary '<已定稿术语表.json>'
```

导出保留初翻当前的全部译文，并自动使用纯文字校对任务卡，不需要手动替换 TASK。按上面的 import-text 接回校对成果后，导出润色包：

```powershell
python lesson.py export-text --stage polishing --work '<同一个work目录>' --editable '<校对接回目录>/editable' --out '<新的润色任务目录>' --glossary '<已定稿术语表.json>'
```

校对与润色必须显式指定 `--editable`；漏传会退出码 2 且不生成任务包。阶段选择不会自动判断译文是否已经完成，负责人仍需选对当前完整版本。当前工作表指纹供交接核对，不取代固定基线，也不新增 TEXT 文件头字段；import 仍按原有基线与 ID 规则处理。

三个阶段都只返回完整 TEXT/NOTE 文件，不同时要求另一种回包。接回后再生成新的完整 editable，让下一阶段继续。可以照 `08-完整接力与修复.md` 跑完整示范。

纯文字格式一条记录三行：ID、TEXT、NOTE，字段值各一行；正文分行用现有占位符，不添加裸换行。多行 notes 的旧工作表不强行压缩，会提示使用完整 editable 模式。程序处理的是约定格式，不从聊天随笔自动识别译文。

## 范围

本入口复用 toolkit 的 `rpgmaker-ai-work-v1` 与其验证规则，支持该工作台实际生成的 JSON/Marshal/源码跨度后端。没有通过无改动闭环的项目，不能先用这个桥接去翻全量。自定义旧工作包、任意 CSV 和未知引擎不因此自动变成可回写格式。
