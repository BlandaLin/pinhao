# 定向复核与成本控制

适用对象：组织项目、建包、接包与验收的人或技术 AI。文字 AI 不需要实现检查脚本。先把一小段完整场景跑通，再讨论全量成本。

## 1. 三种检查，不能混成一个“通过”

| 分类 | 典型内容 | 处理方式 |
| --- | --- | --- |
| 结构硬错误 | 错基线、未知/重复 ID、只读字段变化、缺记录、控制符缺失或乱序、引擎目标规则不符 | 阻止构建；保留成果，定向修复后重新 validate |
| 文字预警 | 长度异常、术语可能不一致、残留假名、符号变化、可疑断句、重复原文的译法差异 | 提交上下文复核，不自动改译文、不冒充误译结论 |
| 语义结论 | 人称与主客体错误、否定翻反、漏条件、角色关系误判、情绪失真 | 对照原文和证据，由文字负责人确认与修正 |

本包现有 `lesson.py` 和 `toolkit` 提供结构校验。下表是新增质量预警的设计建议，**不是已实现的语义检测器**。本次没有把来源文档中的示意正则或伪代码当成可运行程序发布。

## 2. 怎样使用代理指标

| 候选指标 | 可发现什么 | 必须保留的边界 |
| --- | --- | --- |
| 去控制符后的可见长度比 | 疑似过短、过长，供优先复核 | 按语言对、文种和已验收样本标定；没有通用健康比例；相同长度也能完全译错 |
| 已批准术语的命中 | 漏用定稿术语或自行换名 | 完整复合词优先；允许已批准别称；检查词边界、动态变量和语境，不靠子串强制替换 |
| 项目指定符号的数量变化 | 风格标记被删除或压缩 | 只检查项目明确指定的符号；不是所有标点必须逐个相等 |
| 残留假名、未经批准的新专名 | 漏译或未定稿候选 | 允许记录过的谜题、原名、拟声等例外；字符扫描不能证明中文专名没有编造 |
| 促音、长音、浊音处理变化 | 声音表现可能被磨平 | 只提示看场景，不能规定唯一中文对应物 |
| 可疑句法、句尾虚词 | 碎句或生硬句法候选 | 先按实际换行控制拆段，再去其余控制符；姓名、颜色等控制符不是段落边界 |
| 同原文不同译文 | 可能的术语漂移 | 必须连同用途、说话人、分支、约束展示，禁止按原文直接全局覆盖 |
| 新出现的外文串 | 未处理词或专名候选 | 角色名、道具、品牌和引用均可能合法；与批准表、原文及例外清单对照 |

规则产生的是队列，不是评分保证。预警过多时先校准规则，不能逼文字 AI 改掉所有被标记项。判断为误报的项记录原因；暂时解释不了的项保持待确认。不能用“机器零警告”宣称全文无错。

## 3. 先做任务卡与小样

负责人填写 `templates/文字质量任务附页.md`：本轮角色、输入版本、已定术语、角色证据、特殊符号规则、质量目标，以及三至五个针对项目难点的正反例。

示范用本项目已批准的小样，不把别的作品的口吻当通用规则。先检查一小段完整场景，观察漏条、主语误判、术语与输出格式问题；有问题先修任务卡与上下文，再扩批。

切批按场景与用途，不按固定字符数从段落中间截断。大小由实测输入量、预期输出量和模型输出上限决定，没有适合所有项目的固定条数。长消息窗、短选项、数据库名词不宜盲目混装。

## 4. 定向返工但不丢已有译文

复核记录至少有稳定 ID、输入版本、原文、当前译文、上下文、问题、证据、建议与结论。可照 `templates/疑点与复核记录.json` 手工填写；它是伴随报告，不是 merge 补丁，也不添加 editable 字段。

只把相关完整上下文与疑点 ID 交给文字 AI。回包仍遵守完整文件或明确的增量协议，不临时改成“按行号猜位置”。技术侧接回前核对输入版本，发现报告已过期就重新核查，不将旧建议直接覆盖新译文。

当前完整译文快照包含之前所有有效修改。若使用本包 baseline-based merge，最终补丁应包含当前全部有效差量，而不是只放本轮校对的几条。重复 ID 先裁决，不能按文件名或后写顺序选胜者。

格式错误不等于全部有效译文必须丢弃。留存回包与报告，定位失败项后修复、重新校验；若只有无 ID 的行式文本且已经错位，先恢复可信映射，不能勉强定向认领。

## 5. 抽查不能只看被机器抓到的条目

重点检查人称、主客体、条件、称呼、选项后果、复合术语和拟声；同时从没有预警的条目中抽样，避免只发现“正则擅长发现的错”。抽样数量随项目风险、规模和样本结果调整，不预设万能比例。

抽查发现同类错误成片出现，就扩大相应类型的核查范围。只检查了一部分就报告那一部分，不写“全剧情逐句通过”。可读性抽查、语义对照、结构校验、显示验收、实机试玩分开留状态。

## 6. 节省的是重复工，不是证据

每轮只发职责所需的任务卡、当前译文、有关上下文和术语子表，不重复塞整段聊天历史。上下文子表应包含理解句子所需的关系，不能为了省 token 删掉关键说话人或前后因果。

保留稳定 ID 的格式开销：它能阻止错位并支持定向返工。本包纯文字接口已经把 JSON 结构管理交给程序，文字 AI 只改 `TEXT/NOTE`。不要再为了几行 token 改成没有 ID 的位置对应。

中断后以落盘文件和实际校验报告确定完成范围，不相信聊天里的“已完成”。限制并发的写入范围，一个文件/批次只有一个当前负责人；下一阶段使用上一阶段完整有效输出。

记录输入、输出、缓存计费项、失败重试和实际账单，按服务商当时规则估算费用。缓存命中率不等于同等比例的费用折扣，不给出“必省几倍”或固定并发数承诺。

处理不了的批次如实标记未完成，缩小范围或补足上下文后再安排；必要时交给合适的文字人员。不要隐瞒内容、诱导执行者绕过自己的限制，或靠反复重试烧钱。

## 7. 发布前收口

冻结术语与完整有效译文版本，重新跑结构校验与构建；复查遗留疑点，未解决项列清楚。图片、字体、插件 UI、姓名框、存档里的显示字符串和回想房另外验收。

从最终分享压缩包解压测试，不用工作目录的“成功”代替。排除个人存档、日志、密钥和机器路径；保留必要说明、许可和实际测试范围。教程的中性数据验收并不替代真实游戏试玩。
