# 用三套中性打样学会交包和接包

在解压后的教程包根目录执行以下命令。需要 Python 3.10+；PowerShell 可先设 `$env:PYTHONIOENCODING='utf-8'`。

想先完整照做初翻、校对、润色和错误修复，请直接看 `08-完整接力与修复.md`；本篇介绍三种源格式各自的基础打样。

## 现成材料在哪里

`examples/rpgmaker`、`examples/renpy-template`、`examples/tyrano` 各自有完整练习。教学数据自造，不含真实游戏剧情/运行器。

| 文件夹 | 用途 |
| --- | --- |
| `text-ai` | 未译 editable、术语表、已填 TASK；可直接交给翻译 AI |
| `text-only-ai` | 未译纯文字填写表、只读原文上下文、术语表、TASK |
| `proof-ai` | 已译 editable、术语表、已填 TASK；可直接交给校对 AI |
| `work` | 技术基线与映射，只读；不交给文字 AI 修改 |
| `source` | 自造源格式，用于理解提取结果；不是可玩游戏 |
| `reference/good-editable` | 可行的完整中文参考，不是唯一合法译法 |
| `reference/good-patch.json` | 对应原始基线的最终差量参考 |
| `reference/nochange` | 原样回写输出，与基线字节一致 |
| `reference/built` | 正确回包的数据构建结果 |
| `mistakes` | 控制符丢失、重复 ID、错误基线三种错误补丁 |

RPG Maker 的 proof-ai 中含一条故意补错的人称。角色资料明确 Lin 为男性。Ren'Py/Tyrano 的校对练习没有故意放人称错误，适合熟悉原生翻译模板和标签保护。

## 技术 AI 先跑参考答案

```powershell
python lesson.py check --lesson examples/rpgmaker --editable examples/rpgmaker/reference/good-editable
python lesson.py integrate --lesson examples/rpgmaker --patch examples/rpgmaker/reference/good-patch.json --out '../practice-good-build'
```

应返回 `ok:true`。第二条生成新目录，其中 built 是原生数据/源文件集合，notes.json 是独立备注，result.json 是技术结果。**没有播放器，不能双击运行游戏**。既有目录会被拒绝，不自动覆盖。

换成 `examples/renpy-template` 或 `examples/tyrano` 就是其他两套打样。新 out 名必须不同。除了这些练习，toolkit/demo.py 还有其余提取配置的中性闭环，按 toolkit/guides 阅读。

## 让文字 AI 真正练一次

先生成自己的练习副本，别改随包参考：

```powershell
python lesson.py prepare --profile rpgmaker --out '../my-translation-practice'
```

把 `../my-translation-practice/text-ai` 单独交给翻译 AI，并发其中 TASK.md。它只需要编辑 editable，附简短报告。术语表由负责人定稿；文字 AI 提建议，不擅自改技术映射。这里没有联网翻译调用，只有你选择的文字 AI 实际处理文字。

如果它不擅长 JSON，改交 `text-only-ai`。它只填写每条 `TEXT=` 和 `NOTE=`，不改 ID/BASELINE、不算 hash。不要同时要求它返回两种格式。纯文本示意：

```text
ID=已经填好的稳定ID
TEXT=您好，{{CTRL0001}}。{{LINE0001}}请这边走。
NOTE=如有疑点写在这里；没有可以留空
```

这段仅解释字段，真实文件还有预填版本头和全部 ID。接回后由技术 AI 转换：

```powershell
python lesson.py from-text --lesson '../my-translation-practice' --text '<收到的return-text.txt>' --out '../my-converted-return'
python lesson.py integrate --lesson '../my-translation-practice' --editable '../my-converted-return/editable' --out '../my-text-only-result'
```

现成的纯文本正确回包是 `examples/rpgmaker/reference/good-return-text.txt`，可直接替换上面的 text 参数打样。校对/润色也可在上一阶段有效 return-text.txt 上继续，只改同样两栏，再转换；不能再次从最初未译文本开始。

收到完整 editable 后执行：

```powershell
python lesson.py check --lesson '../my-translation-practice' --editable '<实际收到的完整editable目录>'
python lesson.py integrate --lesson '../my-translation-practice' --editable '<实际收到的完整editable目录>' --out '../my-translation-result'
```

把 `<...>` 换成真实路径；文字 AI 不需执行这些命令。语义由校对人员检查，程序的 `semantic_review:not_evaluated_by_program` 不能改成“全部译对”。

## 看懂错误回包

```powershell
python lesson.py integrate --lesson examples/rpgmaker --patch examples/rpgmaker/mistakes/missing-token.json --out '../practice-bad-token'
python lesson.py integrate --lesson examples/rpgmaker --patch examples/rpgmaker/mistakes/duplicate-id.json --out '../practice-bad-duplicate'
python lesson.py integrate --lesson examples/rpgmaker --patch examples/rpgmaker/mistakes/wrong-baseline.json --out '../practice-bad-baseline'
```

应返回 `ok:false`、退出码 2，不生成成功构建。正确做法是改回包或确认版本，不是删除占位符、修改基线 hash 或按顺序强行覆盖重复 ID。

## 格式通过但文字仍错

```powershell
python lesson.py check --lesson examples/rpgmaker --editable examples/rpgmaker/proof-ai/editable
```

它会结构校验通过，但 semantic_review 明确是未评估。让校对 AI 根据 glossary 和原文找到不该补出的“她”。可改为有依据的“他”，也可保留自然的无代词句式；参考答案只是一种解法，不能用字面完全一致当质量分数。

## 校对和润色之后怎样接回

最简单的方法是始终交**完整的当前有效 editable**：初翻给校对，校对给润色，最终整套表给技术 AI。这样不必让文字 AI理解补丁继承和 hash。

高级增量模式下，`merge` 是“基线 + 本次 changes”，不是“从上次译文再覆盖”。因此校对只交三条改动时，技术 AI 应先在前一阶段完整有效表上应用这三条，检查来源，再生成相对原始基线的**全部最终差量**。不要把初翻补丁与校对补丁一起交给 merge；它会拒绝重复 ID，这正是防止静默丢失成果的设计。

## 你应该学到什么

文字 AI 只看整段内容、上下文和术语；技术 AI 用已有入口验证和回写。完整表模式降低文字人员的编码负担，基线/映射/校验由工具保存。到了真实游戏，再按对应引擎做原生导入、字体与运行验收。
