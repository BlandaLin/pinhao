# 技术 Agent 自主适配

技术 Agent 负责调查资源、选择工具、编写配方，并根据实际验证结果继续修复。
识别失败、提取失败、零文字、显示文字漏提和最终构建失败都能进入技术任务队列。
已有原生适配器完成成熟格式的读写；生成配方补充显示字段，或接管新的资源格式。
用户沿用“配置 API、导入游戏、开始制作”的流程，已验证成果持续接入文字工作台。

文字准备、翻译、校对和成果恢复的协议见 [文字执行与成果接力](TEXT_EXECUTION.md)。

## 工作闭环

1. 原生提取与资源清单建立项目基线，记录已处理资源、未决显示候选、脚本、图片及其他资源。
2. 技术任务复用受管原生解包资源，其他资源建立独立工作副本；内容摘要与文件状态记录支持增量恢复，保留原版和存档。
3. Agent 分页调查整个游戏工作副本、搜索文件、读取文本或二进制片段，查阅公开技术资料并优先调用成熟工具。
4. 编写轻量 JavaScript 适配器或受管脚本型配方，实际执行检测、提取、校验、原样往返、改文小样和组装步骤。
5. 工具返回真实错误和验证结果，Agent 在有限轮次内修改并重测，通过后提交配方。
6. 已验证配方保存适用文件、版本、代码摘要、来源许可证和验证记录，再接入现有制作流程。
7. 成品生成时核对实际输出文件；构建错误携带失败工件返回技术任务，继续定向修复。

再次导入时优先尝试配方，对新资源重新执行验证。技术、翻译和校对共享配置的并发池。
取消保留检查点与已接受译文。新的资源证据、适配方案或模型配置开启相应修复窗口；
同一任务的继续操作沿用已有尝试记录。

## 资源分工与接续

已解包项目的独立文件分成稳定资源任务，执行槽计入已有全局并发池。
完整沿用设置中的“同时处理任务”上限，范围为 1 至 32；独立资源按可用槽位调度。
每个任务拥有独立范围、模型消息、有效工具证据、代码候选与验证记录。
通过验证的文件与局部配方逐份接入文字工作台，其他资源继续处理。精确定位同时核对原生与补充绑定，
保留已有文字、译文与修订。默认让通过回写检查的文字继续翻译、校对和成品制作，
剩余资源保留原文与补漏记录。“遇到局部失败时暂停”设置保留严格流程，项目提供“用已提取文字继续制作”入口。
成品记录文字覆盖、保留原文和实际游玩检查；“提取剩余文字”继续处理未决任务。
取消和继续保留完整任务集合及已接入成果。

配方复用按当前资源实际覆盖选择，优先核对上次有效版本。已无候选的旧文件任务直接收束。
长输出采用有限的工具接续；成功批次、待解决错误的重试次数和执行窗口分别计数。
活动、真实新材料、已接受配方与数据库接入分别记账。参数变化、脚本退出、重复日志和候选代码版本不刷新成果时钟；读取只按宿主核对的来源与实际新字节区间记录材料。
空结束保留重试入口，重复错误和连续无进展分别记录停止原因。
同一基线的继续操作沿用失败记录，界面提供剩余资源和模型调整入口。
同一技术请求共享累计 HTTP 与窗口预算，包含独立显示复核、兼容重发和失败请求；换模型、暂停或重新分工不重置。费用缺失记为未知，已落盘终结收据可按原请求补账。旧记录缺少完整总账时不假定历史免费，须明确追加额度。
原生解析器、工具版本或可用能力更新时，旧失败项目重新尝试当前原生路线，成功后重新生成资源任务。

技术工具记录开始、耗时、模型步骤和结束原因。同参数读取在本轮缓存，检查点保留完整的工具消息组，
模型继续时沿用已确认资料。单次模型请求采用独立超时，超时与取消均保存可接续记录。

原生提取的完整结果保存在主机，模型收到结果编号与数量，通过 `native_inspect` 分页查看。
`native_accept` 完成原样回写检查后，将主机结果接回文字工作台和成熟构建器。
原生组件待审、提取异常与字体排版记录分别分类。待审组件按载体和类型组织技术任务，
独立载体沿用全局并发设置；已提取文字可先继续翻译。
Unity 自定义组件通过 `native_review` 查看类型、字段样例和资源证据，
通过 `native_review_decide` 选择显示字段或确认非显示用途。主机核验当前资源、原样往返和改文小样，
再将新增文字接入当前工作台；已有文字 ID、人工译文、备注和其他适配绑定保持原样。
模型使用返回的 `groupRef`（如 `g1`）和字段内 `siteRef`（如 `s1`）；主机绑定该次实际观察的
原始组、资源摘要和显示消费点。新观察不改写旧引用的含义，底层原生校验继续核对资源基线。
同一引擎操作指南在系统指令中提供一次，`inspect_context` 返回章节入口并支持按需补读。
同一次请求历史中的相同工具结果保留第一份正文，重复项引用本地完整证据；不同结果与分页保持独立。
这些是传输调整，不减少调查、脚本执行、公开资料检索或并发能力。
字段决定保存在工作台中，暂停或重启后继续处理剩余组；原生资源快照由各次扩展共用。
Unity Mono 的程序集完整常量句可以沿数组到显示控件的实际消费链提取，并在经核验的显示点映射译文，
原数组、存档键及其他逻辑用途保持原值。逐字显示在完整句进入显示链时映射；动态拼接模板单独保留待处理记录，
不把拼接片段当成完整对白。已完成项目可通过“检查遗漏文字”重新发现新增原生能力覆盖的来源。
每份工具完整输出保存为证据工件，实时消息携带摘要与 `evidenceId`。
Agent 使用 `read_evidence` 读取具体字段、长文字、日志和后续数组页；证据编号随任务检查点保留。
`read_evidence(action:search)` 可按工具、资源、运行编号、工作项及原文字面量检索发生回执。同一正文只存一份，每次调用另留小回执；恢复读取不冒充新发现。
未交付发现可用 `manage_work_items` 保存精确定位、来源和消费者回执、阻碍与下一步。脚本可输出 `pinhao-investigation-findings-1` 工件，由宿主逐项核对再导入；原 writer 仍可直接调用，文字选择 writer 也可通过 `itemIds` 复用已保存选择，不新增审批前置。
检查点回退时按各自 namespace 重放回执；未知写入保留待核对，不盲目重做。联合资源分工只在原池已结束后转交发现与失败记录，不合并对话或重新赠予预算。
分页游标按实际返回内容推进，多组数组各自提供后续位置。
同一资源的已验证批次按稳定定位累计，后续批次保留前面批次的回写绑定。

独立资源可以并行处理。索引与数据等关联文件需要共同修改时，Agent 调用 `request_scope_change`
申请联合范围，协调器合并相交任务并重新安排分工。已有接入成果和其他独立资源继续保留。

## Agent 工具

| 工作 | 可用工具与结果 |
| --- | --- |
| 了解任务与范围 | `inspect_context`、`inspect_coverage`、`inspect_units`，查看覆盖记录、已有定位、任务范围和能力表 |
| 查看实际资源 | `list_files`、`search_files`、`read_resource`，分页目录、内容检索和文本／二进制片段 |
| 补读完整证据 | `read_evidence`，按 `evidenceId`、字段和游标读取主机保存的完整结果 |
| 查阅公开资料 | `search_public`、`read_public`，读取公开引擎、格式和工具资料 |
| 使用成熟解析器 | `run_tool`，调用登记的原生提取、检查、解包与重封包能力 |
| 编写与修改配方 | `write_adapter` 保存 JavaScript 对象，`write_python_adapter` 保存 Python 模块；`read_adapter`、`patch_adapter` 读取和按代码哈希修改候选 |
| 运行调查脚本 | `write_workspace_file` 保存脚本与任务笔记；`run_workspace` 启动受管进程；`read_run` / `wait_run` 读取同一进程的分页输出和退出状态 |
| 调查局部行为 | `preview_adapter`、`run_probe`，执行局部预览或指定译文小样，返回真实日志与检查结果 |
| 接入显示文字 | `write_text_adapter`、`validate_adapter`、`submit_recipe`，从精确候选形成经过验证的回写配方 |
| 调整覆盖判断 | `record_coverage_decisions`，记录未知字段簇的显示用途及依据 |
| 协调与返修 | `request_scope_change`、`read_failure`，申请关联范围，查看返修包和失败工件 |

能力表记录工具版本、格式范围和限制。工具返回的结果进入完整证据存储，后续调用可以继续查看。

模型审阅候选用途后，可按候选 ID 调用 `write_text_adapter`。主机核对当前 JSON 字段或引号字符串原文，
生成标准 JSON pointer／UTF-8 区间适配器；生成代码继续经过相同的隔离执行、往返、小样及结构检查。
手写适配器与登记工具用于其他格式和复杂结构。

受管原生资源按只读能力复用。独立源副本保留原内容摘要与增量校验记录，重试跳过未变化项，补齐缺失或损坏项。
原生扫描已确认的零候选资源沿用原扫描结果；JSON 字段与脚本候选均按精确定位及原值核对覆盖情况。

## 归档与配方复用

`native_unpack` 返回成员目录、完整成员清单、大小和内容摘要。适配器通过归档成员视图读取资源，
使用现有 JSON 指针或 UTF-8 字节定位完成改文。`native_repack` 将修改重新放入容器，
同时保留其他原始成员，并回读核对成员内容。

当前登记工具提供 ZIP、XP3、RGSS v1 和 PCK 的解包与重封包，RGSS v3 提供提取能力。
相同源内容和成员内容复用已有工件；变化的内容使用对应的新身份。
Unity Mono 原生路线在具备对应托管程序集时，使用元数据恢复剥离的显示组件类型树。
载体、成员、`fileID` 和 `pathID` 共同定位对象，完整字段、非文字数据与资源引用继续参与原生校验。

验证证明绑定候选代码、实际读取的文件、目录清单、缺失文件查询、工具与检查器版本，以及小样计划。
同一证据身份可以复用已通过的验证。读取依赖、代码或检查环境发生变化时重新验证，
包括后来出现的可选文件和新增目录成员。

## 执行与验证

轻量 JavaScript 配方在独立工作线程的 QuickJS WASM 中执行。主机按清单提供文件能力，写入限定在输出目录；
这一执行路径中的环境变量、进程与网络由主程序掌管。目录链接、最终文件链接和共享硬链接在输出前核对。
公开资料工具核对 DNS 地址和每次重定向；已登记的成熟工具使用固定主机回调或命令及参数规则。
适配器支持对象表达式和返回对象的程序体，`host.log` 将调查日志保存在工具证据中。

项目授权后，Agent 还可在游戏工作副本、项目脚本和产物目录中使用受管本地执行。
首次启用界面说明权限，用户明确授权后生效；暂停任务后可在制作总览撤销。
脚本以当前 Windows 用户权限运行，可以自行访问该用户的其他文件和网络。宿主文件工具继续核对范围、链接与输出归属，
主程序不向脚本传入 API 密钥。系统级安装、提权、额外外部目录和上传资料分别取得授权。
stdout 与 stderr 分开保存为本地工件；等待结果使用原运行编号，取消等待完整进程树退出。
重启后保留脚本与证据并标记中断，Agent 依据实际产物决定下一步。
项目依赖环境记录版本和来源，继续复用主程序原有的原样往返、改文回读与结构校验。

Python 配方采用 `python-module-v1`：模块定义 `detect`、`extract`、`validate`、`roundtrip`、`build`、`assemble(host,input)` 六个同步函数。
宿主统一实现进程通信、动作分发与结果序列化，不再要求模型编写 stdin/结果文件 CLI，也不自动兼容旧 CLI 配方。
`write_python_adapter` 填写运行时和协议；额外只读输入用 `readFiles` 声明。`host.readBytes`、`host.writeBytes` 使用 base64 字符串，
`host.list` 只列声明资源，完整游戏调查仍用已有文件工具。该接口不是操作系统沙箱，不改变上述当前用户执行权限。

新增配方完成机械检查后，独立用途复核使用现有技术模型配置，逐项调查实际来源、加载入口和显示消费者。
它不接收作者会话或“这是显示文字”的自述；全部提取单位分别记录已证显示、非显示或待确认，未全部证实则不晋升该配方。
这一步会产生正常模型费用；已完成裁决按代码、源文、模型及来源/消费者依赖复用，待定批次只续核未决项。
调查中已完整返回的模型/工具消息组保存为单份检查点；取消后核对身份和依赖再接续，未返回的半组不充当完成证据。
消费者变化后重新验证。现有成熟原生提取不因此逐条重新购买复核。
用途复核与结构检查、实机结果分别记录，静态消费链证据仍不等于实际游玩验收。

主程序分别核对：

- 稳定 ID、源文、上下文和可回写定位。
- 原样往返的全部声明资源字节。
- 多位置、变长中文和组合改文后的重新提取、保护标记和原资源引用。
- JSON 指针允许的文字差异，或 UTF-8 字节区间之外的原始字节。
- 其他二进制格式提供的可信结构校验器。
- 新增配方全部文字的独立显示用途复核及来源、消费者依赖。
- 已登记实际运行器提供的独立检查记录。

脚本文字同时经过语法检查：JavaScript 比较真实语法树，GDScript、Ren'Py 与 Godot 场景文本
核对字符串边界及引用方式。普通 TXT、CSV、TSV 使用限定字节范围；其他格式由可信结构校验器扩展。

原生与补充适配各自保留绑定。补充文字按 ID 分流到相应构建器，原生容器使用原生组装路线。
同一 JSON 资源按字段指针合并；UTF-8 资源按基线字节范围映射原生改动，保留两条路线的有效译文。
重叠修改或重复字节造成定位歧义时保留技术进度，继续核对合并方案。
原生 build 与摘要报告保持封存，已校验的文本覆盖文件在独立组装阶段进入原有容器。
PNG 重绘沿用独立图片通道。

最终构建、补充文字合并或运行检查失败时，主程序在清理前保存返修包：
基线身份、工具版本、文字与修订、回写绑定、错误阶段和实际失败工件。
Agent 通过 `read_failure` 获得工件编号，再按相对路径只读查看文件；完整结果仍可通过 `read_evidence` 补读。
修复配方接回现有工作台时核对稳定身份，已有译文和人工修改继续保留。

## 覆盖与进度

文字处理百分比针对已经提取的文字单元。资源覆盖记录单独列出未决候选，
同一个脚本里已经提取的文字、行内显示调用、间接表达式和其他待绑定显示位置分别记录。
字体布局提醒、逻辑身份和控制流标签使用对应分类；图片候选沿用项目的图片处理设置。
共享术语阶段显示独立完成数，批次提示只携带相关已确认术语。
覆盖检查发现剩余缺口后，将具体资源与候选返回 Agent，继续执行验证循环。
语言资源目录同样参与调查。未知 JSON 字段按结构聚成字段簇，携带资源内容摘要和原文样例。
Agent 结合加载代码与上下文，将字段簇判定为显示文字或其他数据，并保存依据。
显示文字转成精确提取候选；其他数据保留判定记录。资源内容变化后重新核对决定。
分类决定同时绑定资源清单、脚本与配置内容，以及实际调查过的源文件片段、目录和缺失路径。
新增插件、同尺寸脚本改文或原先缺失的目录出现后，相关旧分类重新进入调查。
相同证据身份的分类保存到本机配方库，其他项目再次导入时可以直接复用；大体量媒体沿用清单，
实际补读片段按原偏移核对。
配方的结构验证、资源覆盖以及实际游戏运行各有独立结果。
进度分别记录已处理、通过、已收束、待处理资源，以及本轮新增、累计接入文字。
字体引用和标准 JSON Schema 元数据按实际语法结构分类，日常对白中的同名文字继续保留显示候选。

## 大型项目调度

每轮调度读取一次持久任务，建立指纹与恢复输入索引；批次查重沿用精确指纹优先、最近可恢复任务优先的规则。
已排队任务直接复用，新增或状态变化即时更新本轮索引。术语审计复用项目快照，以集合查询已有审计记录。
文字表使用项目与位置的联合索引，分页和完整读取沿用原来的文字顺序。

## 回归样例

中性用例覆盖未知格式首次适配、错误反馈修复、再次导入复用、原生补充资源、
取消后重开恢复、局部成果逐份接入、九项任务实际并行、模型切换、重复错误、
长输出接续、完整证据分页、原生版本恢复、证明依赖变化、联合资源范围、
未知字段簇判断、代码与验证证据身份、目录链接、字节区间和控制符。
模型响应使用本地模拟服务；SDK、QuickJS、真实文件、持久配方和构建路径实际执行。
归档回归实际执行解包、生成配方、验证、构建、重封包和回读，核对改文与其余成员。
结构测试、进程启动、中文画面以及分支／存档游玩分别留存结果。
各引擎的具体能力与测试范围见 [原生引擎支持](NATIVE_ENGINES.md)。

## 源码入口

- `packages/technical/adaptation.mjs`：工具循环、修复窗口与持久检查点。
- `packages/technical/adaptation-pool.mjs`：稳定资源分工、受限并发与覆盖汇总。
- `packages/technical/coverage.mjs`：资源覆盖与缺口分类。
- `packages/technical/research.mjs`：公开资料检索与读取。
- `packages/technical/adaptation/`：隔离执行、适配器注册与主机验证。
- `packages/core/native-tools.mjs`：登记原生工具、归档成员视图与回执。
- `packages/core/adaptive-worker.mjs`：原生与补充适配路由、工作副本。
- `packages/core/service.mjs`：制作队列、恢复与成品接入。
- `packages/core/build-repair.mjs`：失败构建工件留存。
- `packages/core/output-manifest.mjs`：成品内容身份与复用核验。
- `packages/core/task-index.mjs`：单轮任务查重与恢复索引。
- `packages/core/store.mjs`：文字顺序索引与持久存储。
