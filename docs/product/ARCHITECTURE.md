# Agent 汉化产品技术架构

状态：0.5.8。本文记录产品分层与扩展接口；技术执行的当前合同以
[DSH 运行时](DSH_RUNTIME.md)为准，实际完成项见[实现进度](IMPLEMENTATION.md)。

## 一 技术栈

采用 **Electron + TypeScript/React + SQLite** 作为桌面产品和作业核心，现有 Python 解析与校验代码通过进程协议复用。
首发为 Windows 10/11 x64，可处理受支持的 32 位游戏。Windows 专项窗口、输入和受限执行
保留小型原生宿主接口，具体实现随运行期功能接入。

| 层 | 推荐选择 | 原因 |
| --- | --- | --- |
| 桌面外壳 | Electron | 固定 Chromium/Node 环境，界面与后台通信成熟，便于统一发行 |
| 界面 | React + TypeScript，静态打包 | 共享命令/事件类型；专业工作台，不需要 SSR 或远程网页 |
| 作业与 Agent | 独立 TypeScript 包和后台进程 | 与界面解耦，CLI/测试可以调用同一核心，不依赖 UI 存活 |
| 技术执行与模型协议 | DSH 技术运行时；文字侧模型网关与 AI SDK | 技术循环归 DSH，业务验证与文字协议归产品 |
| 项目数据 | SQLite + 文件产物 | 事务化保存状态与版本，大资源留在文件系统 |
| 既有解析器 | 随产品提供的固定 Python 环境 | 复用已验证代码，不要求用户安装 Python |
| 引擎扩展 | 进程外适配器与引擎内小型运行桥 | 允许 Ruby/Python/JS/.NET 等工具各司其职 |
| Windows 专项 | 原生能力接口，按需补充小型宿主 | 键盘、窗口、截图、进程树管理与受限执行接入 |
| 分发 | Windows x64 便携目录与分享 ZIP | 携带固定运行环境、原生工具、字体、源码与许可证 |

Electron 的主进程、renderer 和 utility process 提供了现成分工，但后台进程不是自动获得文件与网络限制的安全沙箱。[官方进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)

这项推荐优先考虑现有 Python 资产、Agent/模型接口开发和完整产品的实现成本，不是认定 Electron 体积最小。Tauri 使用系统 WebView，安装体积有优势，但若另带 TS 执行内核仍需 sidecar；本项目会增加 Rust 与跨进程集成工作。[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)、[sidecar 分发](https://v2.tauri.app/develop/sidecar/)

.NET/WPF 也能完成 Windows 产品，但 Windows 专项需求可以由辅助宿主满足，暂不以此要求重写全部主程序。若用户把极小安装体积或纯原生 UI 设为第一指标，应在实现前重新比较，而不是开发中途换壳。

当前锁定 Electron 44.8.0、AI SDK 7.0.142、OpenAI-compatible provider 3.0.70，
SQLite 使用 Node.js 24 的 `node:sqlite`。Python 发行环境为 3.12.10 embeddable；
默认字体为霞鹜文楷 1.522，随带 OFL。精确依赖由根 `package-lock.json` 与准备脚本记录。

## 二 进程与依赖方向

```text
桌面 UI
  | 类型化命令与事件
本地主机服务
  |-- 密钥代理、文件选择、权限和进程生命周期
  |-- 持久作业内核
        |-- Agent 执行与模型网关
        |-- 项目与文字版本库
        |-- 工具代理 -> Python / 引擎适配器 / 必要外部工具
        |-- 构建与发布器
        |-- 游戏运行桥 -> 动态采集 / 布局反馈 / 游玩辅助
        |-- Windows 测试助手 -> 指定窗口 / 截图 / 键盘 / 进程状态
```

界面只发送业务命令，不直接执行 shell、修改数据库或持有游戏文件写句柄。解析器不知道 React/Electron；Agent 不能绕过提交接口自行宣布结果。游戏运行桥不持有 API 密钥。

采用模块化本地应用，不上微服务、Redis、Kubernetes 或必须连接的产品后端。进程划分用于隔离生命周期、崩溃和权限，不把每个业务函数变成一个服务。

## 三 Agent 内核

内核不是“一个永远追加的聊天记录 + 任意 shell”。由持久任务调度器保存目标、当前计划、尝试记录和产物；Agent 决定具体工具选择、例外处理和子任务调整。

阶段规定输入、输出和验收条件，不把所有游戏强制写死成同一个脚本。Agent 可以增加适配、诊断和修复子任务，新增任务由统一调度器按项目范围、依赖、执行限制和权限派发。

技术、翻译、校对和 OCR 工作由产品任务池与请求控制统一管理，默认并发为 3，
可在 API 设置中调整。技术作业各有独立 DSH 会话，执行模型循环与工具选择；
任务分配、请求记录、验证、成果接入与恢复仍由产品负责，不在 DSH 外叠跑旧模型循环。

产品提供版本化默认任务卡，覆盖技术适配、初翻、校对、OCR 和定向修复。任务卡明确角色职责、输入材料、允许修改字段、产物与结束条件；上下文装配器填入当前场景、术语、版本和疑点。普通用户选择游戏与模型后即可开始，提示词维护留在产品与开源配置层。

内核围绕以下组成实现：

- 模型调用接口：流式输出、工具调用、可选原始用量、取消和明确错误。
- 工具注册表：有结构化输入输出、权限声明、超时和产物声明的可调用工具。
- 上下文装配：项目事实、当前任务、必要配方、来源片段和近期执行摘要。
- 任务提交器：检查结构、版本与产物后事务提交，模型文字本身不等于提交。
- 调度与恢复：全局并发、任务去重、结果复用、检查点、有限重试和请求不确定性记录。
- 执行结束条件：任务与阶段分别声明工具轮数、输出长度、尝试次数、超时及提交条件。

当前技术 Agent 使用固定版本 DSH 处理模型循环、会话和工具调用，原有业务工具通过插件接入。
宿主负责验证候选、接受结果与新增文字接入；模型回复“完成”不是业务成功回执。
文字侧保留独立的翻译/校对协议与模型网关，不因替换技术 Harness 而更换文字流程。

供应商通过显式 provider 实例直连用户填写的地址，不要求 Vercel 账号、云部署或 AI Gateway。兼容接口可以使用其 OpenAI-compatible provider，具体能力仍做实测。[自定义供应商地址](https://ai-sdk.dev/providers/openai-compatible-providers)

UI、领域任务与运行时通过内部接口隔离。固定依赖、Node 载体、请求中继、恢复身份与
工具回执详见 [DSH 运行时](DSH_RUNTIME.md)。技术 Agent 可在项目授权后编写并运行脚本，
以当前 Windows 用户权限执行；这是受管执行，不是操作系统强隔离环境。

上下文按引擎、来源、符号和场景组织，仅装配当前任务相关材料。当前使用本地索引与明确引用，
向量检索和专用模型作为可选扩展。

## 四 模型直连与执行控制

用户配置供应商、URL、模型和密钥。兼容协议适配器与供应商专用适配器分开；仅声称 OpenAI-compatible 不代表工具、结构化输出、流式和用量字段完全兼容。

模型配置记录能力测试结果。技术任务检查工具调用能力；文字任务检查结构化返回与批次完整性；图片任务另检查视觉能力。无法完成某项职责时给出原因和替代配置，不用伪造工具调用补齐。

每次调用记录任务、阶段、输入版本、任务卡版本、模型、请求指纹、供应商请求 ID（若有）和返回状态。供应商返回的原始 usage 可以作为可选诊断数据保存；缺失时标为未提供。密钥不写入记录。

产品采用用户自带 API 的供应商直连模式。供应商计价与账单由用户和供应商管理；产品不维护单价表、金额预算、费用估算、额度预留、积分或费用结算。

调度器记录排队和在途任务，按全局并发限制派发；相同任务范围、输入版本、任务卡及配置已有有效成果时复用结果，避免重复执行。每项任务设置有限尝试次数、工具轮数、输出长度和超时，达到条件后提交成果、转入定向修复或报告待处理项。

局部失败默认在有限重试后保留基线文字或原图、标记跳过并继续；`pauseOnLocalFailure` 可切换为暂停。
持续接口故障、核心文字任务整体失败与解包/原生构建失败暂停对应阶段。歧义通过备注与问题登记保留，
制作正常推进。`processImages` 默认关闭；开启后，视觉 OCR、图片文字接力与平整背景 PNG
回写进入同一任务流程。复杂背景和未处理区域保留原图并记录。

断网或崩溃后的未知请求先核对可取得的状态，不保证跨任意 API 的 exactly-once。没有可查询请求或幂等能力时保留不确定记录，按明确的重试条件与次数处理；恢复从检查点接续。取消停止后续派发，并向在途请求传递取消信号；服务端状态单独记录。

## 五 项目与文字数据

| 实体 | 保存什么 |
| --- | --- |
| Project | 游戏身份、原版指纹、目标、输出位置、配置引用 |
| SourceRevision | 一次扫描的资源清单、引擎/插件信息和内容指纹 |
| TextUnit | 项目内身份、类型、源文、保护标记、上下文及版本 |
| Occurrence | 引擎定位、场景/事件/字段、显示用途和关联单元 |
| TranslationRevision | 当前译文、父版本、阶段、作者/模型及备注 |
| Term/Name | 术语、名字、别名与适用范围，不混入玩法标识 |
| Task/Attempt | 计划依赖、状态、输入指纹、任务卡版本、执行限制、工具或模型尝试 |
| Artifact | 产物位置、摘要、生成任务、依赖版本与有效性 |
| Issue/Evidence | 问题位置、来源、截图或验证记录、解决状态 |
| Build/Release | 使用的源文/译文/配方版本、文件清单、验收与输出 |

源文、译文和出现位置分离。同源句可以共用建议，但不同人物或场景可以有独立译文。引擎逻辑 ID、资源路径、表达式和显示文字不存成同一类可翻译字段。

现有 manifest ID 作为 legacy exchange ID 保留，并与冻结 manifest 指纹绑定。产品使用项目级身份；游戏更新后以引擎结构、原文和邻接锚点重定位，无法唯一匹配的进入待确认，不按新行号套用旧译文。

旧 CLI 的 JSON 继续作为适配器交换格式，不直接升级为唯一产品数据库。新增阶段从明确 TranslationRevision 导出，回包只有允许字段可变；检查通过后才形成新修订。

SQLite 由核心单一提交路径负责写入，长模型调用不占用数据库事务。事务用于状态、版本和产物登记的一致性；大文件先写临时产物、校验后发布，再登记可用性。文件与数据库不是天然跨介质事务，重启时要能识别未登记或不完整产物。

WAL 允许读写并行，但仍只有一个同时写事务；活跃数据库备份采用 SQLite backup API 或一致性快照，不只复制裸 db。[SQLite 事务](https://www.sqlite.org/lang_transaction.html)、[WAL](https://www.sqlite.org/wal.html)、[备份](https://www.sqlite.org/backup.html)

## 六 适配器契约

适配器通过版本化 JSON 消息和文件产物通信，业务日志与协议消息分开，不能让一行调试输出破坏结果解析。大资源传相对产物引用，不通过 IPC 搬运整款游戏。

统一职责包括 probe、inventory、extract、validate、roundtrip、build、assemble、launch、runtime capture、layout、save display migration、assist。可以分模块实现，不要求每个适配器声称全部支持。

每项能力声明支持版本、前置工具、输入、输出、修改范围和验证方式。assemble 负责独立游戏副本；现有 build 只负责已记录数据文件，两者明确分开。

动态采集返回来源线索、原始显示串、控件/事件、当前字体和可用截图定位。不能定位到静态来源时可以登记运行期覆盖配方，不声称已找到所有原生文本。

每次构建固定配方与工具版本。Agent 生成的新适配先存在项目私有区，测试通过才可供本项目使用；提升为公共配方需要中性回归样例、依赖与权限清单，不自动执行来源不明的插件。

## 七 作业恢复

项目总体阶段与子任务状态分开。子任务至少区分 pending、running、waiting-user、paused、succeeded、failed、cancelled，
并记录默认跳过的局部失败；程序崩溃时遗留 running 重新核对，按检查点恢复。

检查点位于提取、原样回写、小样、已接受文字批次、补漏、构建和验收之间。每个批次提交后即可恢复，不以整场对话是否结束作为保存条件。

重跑条件依据输入指纹与产物有效性。更改某个人名或字体，只使相关任务和构建失效；不删除已通过的其他批次。失败产物不能被下游默认消费。

暂停停止派发新任务并处理在途操作；取消终止本次计划而保留已接受成果；退出保存可恢复状态。设置是否允许后台继续时，界面必须讲清进程与 API 是否仍在运行。

文件副作用在项目副本里完成。原版、外部存档和其他项目不是恢复时可随意覆盖的目标。

## 八 权限与执行边界

桌面渲染进程开启 context isolation 与 sandbox，不加载可执行的游戏 HTML/脚本作为产品 UI。文件预览与游戏文本是数据；导入材料中的“指令”不能提升工具权限。[Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)

密钥由主机侧代理按供应商请求提供，不出现在模型上下文、游戏运行桥、适配器环境或导出包。系统加密保护落盘，但 Windows 的 DPAPI 不阻止同一登录用户下的其他进程读取，因此不能只靠 safeStorage 保护任意生成代码。[safeStorage 边界](https://www.electronjs.org/docs/latest/api/safe-storage)

分开处理随产品发行的可信工具、Agent 生成的脚本和实际游戏进程。工具代理校验路径、解包目标、文件写范围与网络去向；原版只读，写入项目产物区。实际游戏在用户明确启动后运行，不声称它因此变成可信代码。

Agent 生成代码的自动执行需要真正的受限宿主，不能只设置 cwd 或启动子进程。Windows 的进程树、超时与资源限制可使用 Job Objects；文件与网络访问仍需额外的受限令牌、访问控制或适用 OS 沙箱方案，具体机制列入执行宿主验证。[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

当前执行宿主运行随产品发行的可信工具。Agent 生成任意新代码的自动执行随受限宿主验证接入；
该路径的文件、密钥、网络和子进程边界通过后，再向普通自动任务开放。

普通任务持续执行，局部异常与语义疑点按默认保留策略处理。新增执行权限、启动游戏或覆盖外部文件
使用明确动作入口；项目结束后集中展示处理摘要。

## 九 实机与发布

Windows 测试助手只针对已选游戏窗口收集截图和输入，不控制无关应用。游戏界面可由引擎状态、截图和真实键盘共同验证；UI Automation 不等于能读懂任意游戏画面。

输入要验证焦点与游戏响应。SendInput 受权限完整性限制，调用成功或已发送按键不能当成场景已推进。[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

发布器将原资源、变更文件、字体和必要运行桥组装到新目录，验证缺失依赖与旧缓存。独立成品需要在产品关闭后启动；复制到另一个路径后复测，防止依赖开发机路径或私有缓存。

缓存与工具包独立计量，可清理、可重建。最终成品不依赖原版目录的硬链接、产品安装目录或当前工作目录。增量补丁另声明适用游戏指纹。

## 十 代码边界

当前真实实现：

```text
apps/desktop              桌面 UI、preload、Electron 主机与开发宿主
packages/contracts        类型化业务命令、设置与产物接口
packages/core             SQLite、项目/文字/构建规则、持久任务与模型调用
packages/exchange         ZIP 工作包的目录读写、schema 与合并校验
packages/technical        技术 ToolLoopAgent、JavaScript 显示文字绑定
packages/runtime          多引擎游戏运行桥、托管适配与游玩辅助
adapters/python           原生编解码、往返、构建、组装、字体与本地化模板
scripts                   固定工具准备、发行打包与公开源码检查
kits/workbench-tutorial   复用的成熟解析器及中性教程
local                     本机项目、测试产物、运行时与发行目录
```

领域、队列、模型与发布规则目前集中在 `packages/core` 和 worker 中，保持单一提交路径。
Windows 专项宿主、生成代码沙箱与更广泛的运行期采集按真实职责继续接入，同一工程复用同一套命令。
