# 拼好汉化产品规格

正式程序位于 `apps/desktop`。本目录维护当前产品决策、架构与验收合同，
实际能力与验证范围见 [实现进度](IMPLEMENTATION.md)。

## 已确定的方向

产品面向 RPG Maker、同人游戏和相关轻型引擎生态。用户选择游戏、填写自己的模型 API，由软件内置 Agent 组织技术处理与文字工作，得到可游玩、可继续修订、可独立输出的汉化版本，并提供对应引擎的游玩辅助。

默认流程是**先制作可独立运行的汉化版，再开始游玩**。定向补漏与游玩辅助沿用同一项目；
运行期动态采集与更广泛的布局反馈按具体适配继续扩展。

两项核心卖点固定为：**自有上下文翻译格式与文字接力**，以及**无需本软件挂靠的独立内嵌成品**。
界面、持久内核、原生适配与发行一同实施；当前桌面入口为 `apps/desktop`。

开放文字工作包采用标准 ZIP，可在产品内处理，也可交给外部 Harness、文字服务或人工，
再导回同一工作台。格式设计见 [开放文字工作包](TEXT_PACKAGE.md)。

模型采用用户自带 API 的供应商直连模式，账单由供应商提供。任务通过统一队列、去重、
结果复用、有限重试和结束条件管理。默认并发为3，API高级设置可调整；技术和文字任务卡
由产品内置并自动装配。

## 怎样防止方向漂移

实现以本目录规格和验收编号为依据。新建议先判断它改变哪个用户结果、哪个接口或哪个验收项，再决定是否变更规格；不因一次聊天临时加出第二套流程。

内部实现可以拆成多个工程步骤，用户承诺保持完整。跑通提取、展示一个聊天窗口或完成单引擎小样，都不能替代完整产品交付。

正式桌面程序通过同一套业务命令连接 SQLite、Agent、Python worker 和成品组装。
[实现进度](IMPLEMENTATION.md) 区分原生数据验证、模拟模型调用、桌面操作和真实游戏运行证据。
完整产品目标持续有效，按能力补齐与回归，发布时提供准确的版本矩阵。
