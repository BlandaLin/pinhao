# Agent 汉化产品定义

状态：0.5.8 公开版产品目标。本文定义完整产品；实际完成与验证见 [实现进度](IMPLEMENTATION.md)，不将目标功能视为已通过所有游戏验收。

## 一 产品定位

面向普通玩家和民间汉化者，把原版游戏或既有粗译加工成**可直接游玩、可持续校对、可独立输出**的汉化版本的一站式桌面软件。

用户交代目标，产品负责拆包适配、上下文工作台、文字接力、补漏、中文显示、构建和验收。Agent 是实际执行者，不是放在工具箱旁边的聊天顾问。用户不需要先学会命令行、引擎格式、JSON 或其他 Harness。

默认先制作独立汉化版，再开始游玩，已由用户确认。独立版在游戏本身允许离线运行的前提下，不依赖本产品、悬浮翻译窗或模型 API 才能显示已制作的译文。

目标生态是 RPG Maker、同人游戏及相关轻型引擎。重型大型游戏通用汉化不是当前产品承诺。简体中文是首批验收语言，工程数据不写死语种。

首发平台固定为 Windows 10/11 x64 桌面软件，同时处理适配范围内的 32 位老游戏。
其他操作系统后续安排。

两项核心卖点固定为：**自有上下文翻译格式与文字接力**，以及**无需本软件挂靠的独立内嵌成品**。前者把完整语义单元、场景上下文、术语和版本接力交给文字 AI，而非只交付源串到译文的平面字典；后者让已制作译文随游戏副本独立运行。

用户确认产品为中性的本地化工具。开放文字工作包采用标准 ZIP 容器，用户可选择内置模型、外部 Harness、其他文字服务或人工处理，再导回工作台继续制作。格式独立于题材、模型供应商和本产品 UI，文字质量由所选模型、上下文与校对流程共同形成。[工作包设计](TEXT_PACKAGE.md) 定义其核心与扩展。

## 二 用户与任务

| 用户 | 想得到的结果 | 不应被要求掌握的事情 |
| --- | --- | --- |
| 普通玩家 | 配置 API、选择游戏并开始制作，拿到能启动的汉化副本 | 拆包器、字体注入、控制符、提示词、运行时安装 |
| 接手已有汉化的人 | 继承现有成果，定向修补、校对和润色 | 重新制作整套基线、手工按行拼回 |
| 汉化组织者 | 内外部文字接力、处理反馈、发布更新 | 为每次接力重新写合并脚本和提示词 |

三类用户使用同一个项目、同一份当前译文和同一套构建记录。普通路径简单，专业工作台按需展开，不做彼此不兼容的三个产品。

## 三 产品承诺

- 原版不被直接改写；用户存档不默认进入新工程或分享包。
- 成功意味着有可定位的产物和对应验证，不以 Agent 的一句“完成了”改变项目状态。
- 同一项目可以暂停、退出、恢复、补译和再构建，不因新会话丢失已确认成果。
- 初翻、校对、润色继承明确的当前版本，不让校对阶段重新翻译未译基线。
- API 采用用户自备接口直连；任务通过统一队列、去重、有限重试和明确结束条件调度。
- 动态文字、图片文字、默认名字和布局属于同一项目的问题清单，不另外丢给用户自己排查。
- 自动修复、有限重试与原文保留让局部问题留在任务内部；完成页集中呈现处理摘要。

## 四 完整用户流程

| 阶段 | 产品执行 | 用户看到的结果 |
| --- | --- | --- |
| 添加游戏 | 选择目录，识别引擎、版本、插件、已有译文和外部存档位置 | 游戏概要、当前适配等级、建议处理方式 |
| 确认目标 | 选择继承或重译、文字流程、字体与输出位置，其他采用产品默认值 | 一张可以确认的制作计划，而不是几十项工具参数 |
| 技术准备 | 建立原版指纹与副本，选择配方，提取完整文本，原样回写验证 | 能否制作、发现哪些例外、哪些材料已准备好 |
| 小样验证 | 构建完整短场景，检查控制符与原生回写；运行检查分别登记 | 小样检查结果与可打开的测试副本 |
| 文字制作 | 初翻与定向校对，可选润色；或导出外部文字任务后收回 | 当前译文、已完成批次、术语和需要决定的疑点 |
| 技术补漏 | 对照静态资源、脚本显示、动态采集与图片候选 | 增量任务，继承已完成内容 |
| 合成验收 | 组装完整副本，检查标题、选项、对话、存读档和已覆盖回想 | 可启动的测试副本、问题清单、实际验收范围 |
| 使用与发布 | 打开成品、导出补丁或清理打包 | 独立成品、说明、版本与必要许可证 |
| 后续修补 | 将截图或场景反馈附着到原项目，修复并增量构建 | 新版本及明确差异，保留原有成果和回退入口 |

适配能力按项目展示。技术准备或核心构建无法继续时保存成果并暂停相应阶段，用户可重试、换模型或转交外部处理。

## 五 核心功能

### 游戏接入与适配

同时记录引擎族、具体版本、发行格式、插件特征和游戏指纹。识别成功只表示选中了研究或处理路线，不表示原生回写成功。

适配器逐项声明识别、解包、提取、原生回写、独立构建、动态采集、字体布局、存档显示兼容和游玩辅助能力。引擎级能力与具体游戏/版本的验证记录分别展示。

遇到新插件或格式时，Agent 检查材料、选择工具、创建项目级适配、执行样本与回归；通过后才能登记为配方。不会因为目标未知就放弃 Agent 的适配职责，也不把无限研究隐藏在普通任务中。

### 上下文文字工作台

以完整对话窗、段落、选择项或显示字段为工作单元，保留来源、人物、邻接内容、条件、用途与控制标记。相同源句可以共享建议译文，但允许按场景覆盖。

当前工作台有原文、既有译文、当前译文、阶段差异、术语与备注。校对者不需要编辑技术字段。回包按冻结批次和记录身份合并，重复、冲突和错基线不能静默覆盖。

内外部任务共享同一份身份、源文快照与当前译文基线。回包按基础版本、工程当前值、回包值作三方比较；结构化 JSON 和纯文字模式使用同一数据模型，每轮明确唯一填写入口。

现有工具 ID 只在冻结 manifest 中稳定。产品另设项目级身份与版本映射，不把旧的顺序编号承诺成跨游戏更新永久稳定 ID。

### 模型与文字接力

API 分为技术连接与文字连接，可以使用相同或不同的模型。初翻和校对共用文字连接，
不要求用户再为校对新增接口。连接测试只验证相应连接，不等于整款游戏制作验收。

产品提供技术、翻译、校对和润色的版本化默认提示词/任务卡，自动填写当前项目、阶段、术语和上下文。普通用户配置接口、导入游戏并开始任务即可。任务卡随开放文字包一起导出，外部 Harness 可以直接接手；开源材料提供进阶修改入口。

技术、翻译、校对和 OCR 等任务共用全局队列，初始默认同时执行3项任务，API 设置的“高级设置”可调整。Agent 申请子任务，调度器统一派发；任务绑定固定输入版本和产物要求，沿用去重、结果复用、有限重试、暂停恢复及阶段结束条件。

按场景和语义分批，批次保留上下文，不能为凑 Token 把句子切碎。支持已有译文沿用、补漏、定向校对和整套重译。默认组织初翻与校对，深度润色为可选任务。

可把任务交给外部 AI 或人工，再导入原项目。程序校验控制符、字段和定位；语义问题由文字阶段处理。模型输出解释、拒绝或不完整结果时标记异常，不伪装成译文提交。

### 补漏与显示

覆盖数据库、事件、脚本显示字面量、插件参数、动态状态、卡牌/物品说明、名字、回想与图片文字候选。检测先扩大同类搜查，再生成增量文字任务。

图片文字需要定位区域、翻译、重绘和游戏内查看；OCR 候选或图片列表不算完成。可编辑技术控件和复杂美术分别处理，保留无法自动处理的候选。

图片文字处理为可选项，默认保留原图。用户可在制作前开启自动识别、翻译与重绘；软件批量处理，
局部失败保留原图并继续。复杂艺术字以文字清楚、风格协调为目标，比较稿留在工作台供按需审阅。

字体按字形覆盖、风格、测量和可用窗口空间选择，允许用户预览与替换。绘制和测量规则一致，处理换行、分页、姓名框、长选项和气泡；不把统一缩字号当作通用修复。

### 存档与游玩辅助

旧存档默认人名和固化显示值优先通过显示层或明确的默认值迁移兼容。自定义名字、剧情开关和玩法数值不在自动汉化迁移范围内。

辅助区在支持的游戏上提供已验证的金钱、物品、角色、变量、战斗或其他能力，按适配器声明展示。不由模型猜测某个变量就是金币，也不把暂时无能力的按钮放出来假装支持。

翻译制作和修改玩法是两项不同授权。关闭产品前已有游玩成果如何保存、辅助是否修改存档，必须在操作处讲清。

### 成品与分享

完整成品、增量补丁、文字工作包是三种输出。完整成品包含实际启动所需资源；数据 build 目录不能冒充游戏成品。

发布前清理个人存档、密钥、工具私有状态、内部日志和机器路径，保留必要字体与第三方许可证。默认提供免费分享说明；汉化组链接与标识作为可选发布模板，不强制覆盖原作者信息。

## 六 界面结构

| 界面 | 主要问题 | 默认显示 | 按需展开 |
| --- | --- | --- | --- |
| 游戏库 | 我处理过哪些游戏，接下来能做什么 | 项目状态、成品、继续制作 | 引擎诊断和历史版本 |
| 项目总览 | 现在做到哪里，是否要我决定 | 阶段、已有成果和待办 | 工具调用、日志和详细计划 |
| 文字工作台 | 哪里需要改，修改基于哪个版本 | 当前文本、来源、差异、术语 | 控制标记和底层定位 |
| 验收与发布 | 还有哪些问题，能否输出 | 问题、证据、未测范围、导出 | 截图、测试步骤和构建明细 |
| 设置 | 模型怎样配置、存储占用多少 | API、路径、工具包与缓存 | 模型能力、并发和诊断 |

聊天是修改目标和解释问题的入口，不是首页主体。任务列表不要求用户维护。进度说明阶段与真实完成量，不制造剩余时间或假装读取 Agent 的思考。

失败后显示已保留的成果、失败位置和可选动作。暂停、取消、退出和删除项目是不同动作；删除前说明将删除什么，不连带删除原版。

局部文字、图片或特殊显示任务先自动修复并有限重试，仍失败时默认保留当前文字或原图、记录跳过项，
继续其他可独立完成任务。设置提供“遇到局部失败时暂停”，默认关闭。持续接口故障、核心文字整体
失败和解包/构建失败暂停对应阶段。证据不足的人称、关系与词义保留当前文字并记疑点，制作继续。

键盘导航、可见焦点、文字缩放与中文长路径作为基础体验，不在末尾补救。游戏自身的键盘操作与桌面 UI 的可访问性分开验收。

## 七 引擎范围与现有基础

当前已接入多类引擎的原生资源路线，包括 RPG Maker 各桌面系列、WOLF、Unity、Godot
及其他轻型引擎。以下表格保留开发路线说明；最新能力与验证边界以[实现矩阵](IMPLEMENTATION.md)
为准。识别、提取、回写和真实游戏运行分别登记，不承诺同一引擎下所有游戏都能完整制作。

| 路线 | 当前可复用基础 | 后续重点 |
| --- | --- | --- |
| MV/MZ | 产品原生提取回写、完整组装、字体/姓名与 JS 显示绑定 | 特殊插件、实际游戏运行与布局认证 |
| VX Ace/VX/XP | Ruby Marshal 原生读写、RGSS 归档、完整组装与本地化加载 | 特殊 Ruby 显示、字体与实际运行认证 |
| RPG Maker 2000/2003 | liblcf 原生 LCF 读写与事件映射 | stock RPG_RT 代码页、中文字体与实际可运行路线 |
| Ren'Py | RPA2/3 解包、原生 tl 模板子流程 | RPYC/模板生成、启用语言、字体及运行闭环 |
| Tyrano/KAG | 松散 KS 保守子集 | 发行包、宏、TJS/JS/HTML 与中文运行环境 |
| WOLF | WolfTL 原生导入导出、重导出校验、字体与完整组装 | 归档版本覆盖、实际游戏运行与布局认证 |
| Godot/Unity 等 | 原生资源解析与回写、容器组装、字体及项目级技术适配 | 未知/加密资源、动态文字、具体游戏的显示与游玩验收 |

Twine、PGMM、Unreal、GameMaker、NScripter 等现有路线保留在技术目录，不能因存在指南就宣布首发完整支持。具体能力以 [toolkit README](../../kits/workbench-tutorial/toolkit/README.md) 为准。

完整公开版的认证清单按版本与能力列出。当前实现证据与待办集中在 [实现进度](IMPLEMENTATION.md)，
认证范围与既定完整产品目标分别维护。

## 八 执行与存储

API 调用由用户的供应商直接提供和计价。产品采用统一队列、默认并发、去重、结果复用、有限重试及明确结束条件管理执行。金额预算、单价维护、费用估算、额度预留与费用结算已从产品范围移除。

并发设置位于模型连接的高级选项，默认值由产品提供。任务按阶段和输入版本恢复；同类错误只返工相关范围，已接受的译文与产物持续复用。Token 用量可作为诊断信息记录，产品按任务状态和技术限制调度。

原版、项目、中间结果、测试副本和发布成品分开。避免每个阶段复制整款游戏；未改只读资源按需复用，独立导出时物化。不得把可写运行副本硬链接回原版。

先显示预计磁盘需求与可清理缓存。重型引擎工具按需提供，不把 Ghidra、全引擎 SDK 和竞品研究材料放进基础安装包。

## 九 非目标与缺少的材料

当前不做云端游戏托管、社区分发平台、账号计费系统、模型转售平台或通用聊天软件。外部 Harness 集成可以保留接口，但不是普通用户的安装前提。

正式实现采用 Electron + TypeScript/React + SQLite，Python 解析器随产品提供。
`apps/desktop` 贯通实际业务，早期 `apps/desktop-demo` 保留交互参考。后续研究服务于明确的适配问题。

真实游戏兼容与首次使用体验通过社区外测验证。开发侧维护基础结构、宿主启动、模型协议模拟、
任务恢复与成品构建回归；公开前记录实际验收范围、依赖发布清单和资源用量。

这些缺口进入交付验收，不转化为新一轮无边界调研。

## 十 许可与运营

官方软件免费提供，桌面程序与新产品模块采用 GPL-3.0-or-later。允许第三方商业使用，
分发软件改版时履行许可证规定的相应源码义务。开放格式与独立读写库采用 MIT，便于其他项目接入。
既有工具、依赖、字体、游戏资源与用户译文保留各自权利与许可证。项目可以接受推广和赞助。
