# 开放文字工作包设计

状态：0.2 格式契约，2026-10-28；读入兼容旧 0.1 完整包。目标与只读参考明确分离，manifest.taskStage 声明初翻或校对；旧包的阶段明确为 unknown。ZIP、JSON/纯文字编辑和三方合并的参考实现已在
[`packages/exchange`](../../packages/exchange/README.md) 提供。本文保留完整格式设计；
具体可读写字段与当前扩展支持以参考库和 schema 为准。

## 一 已确定的方向

产品提供游戏适配、文字整理、文字工作台与独立成品输出。文字任务可以使用用户在产品内配置的模型，也可以导出后交给其他 Harness、服务或人工处理。两条路径使用同一套单元身份、源文快照、当前译文和回包规则。

格式面向一般游戏本地化与文字协作，独立于题材、模型厂商、账号和本产品 UI。文字质量由所选模型、提供的上下文及校对流程共同形成；产品提供可继承、可检查的工作材料。

工作包使用标准 ZIP 容器，文件名可为 `game_zh-Hans_proofreading.zip`。普通解压工具可以打开，符合规范的软件可以直接导入。包内采用 UTF-8 文本、JSON 与相对资源引用。用户无需注册专用后缀或安装本软件即可阅读和处理材料。

## 二 内容结构

建议结构如下。具体 JSON 字段和纯文字语法随参考实现定稿；实现时保持本文件的身份、版本、上下文与合并语义。

```text
translation-package/
  START_HERE.md
  manifest.json
  source/
  context/
  baseline/
  editable/
  glossary.json
  style-guide.md
  reading/
  references/
  bindings/
  issues.json
```

| 内容 | 核心要求 | 用途 |
| --- | --- | --- |
| `START_HERE.md` | 必备 | 本轮阶段、范围、填写入口、交付规则，以及适用任务说明 |
| `manifest.json` | 必备 | 格式版本、能力要求、项目与包身份、语言、来源和译文版本、任务范围、编辑模式、文件清单 |
| `source/` | 必备 | 完整语义单元、单元 ID、显示用途、原文、保护标记定义和上下文引用 |
| `context/` | 必备 | 本包单元的场景、顺序与关系；已知人物和分支资料按来源提供，未知项显式标记 |
| `baseline/` | 必备 | 本轮导出时的译文快照、逐单元译文版本与任务输入；供接回时比较 |
| `editable/` | 必备 | 本轮唯一的文字填写入口，容纳译文、备注和处理意图 |
| `glossary.json` | 按需 | 有适用范围与版本的人名、称呼、专名、批准译法及待确认建议 |
| `style-guide.md` | 按需 | 人物口吻、表达约定、批准小样及对应来源 |
| `reading/` | 按编辑模式生成 | 按场景阅读的原文、当前译文和上下文；为阅读视图，数据可由核心内容重建 |
| `references/` | 可选扩展 | 截图、图片文字区域和其他明确引用的参考材料 |
| `bindings/` | 游戏绑定扩展 | 引擎与适配器版本、相对资源定位、源文指纹、回写映射等技术材料 |
| `issues.json` | 按需 | 附着到具体单元或参考材料的疑点、反馈、证据和处理记录 |

文字工作包与完整工程备份分别导出。工作包集中携带文字任务与接回所需的身份信息；游戏本体、运行环境和构建工具由接收方本机工程提供。导出采用公开字段白名单，API 密钥、私人存档、内部日志及本机绝对路径保留在本机。

## 三 核心数据契约

### 1. 身份与出现位置

格式分别记录项目身份、源文版本、单元身份和出现位置。单元 ID 为项目内的持久身份；内容指纹用于比较内容，文件顺序和原文字符串用于定位辅助。相同源文允许处于不同单元并具有不同译文。

一个显示用单元可以关联一个或多个明确的出现位置。适配器可共享确认一致的出现位置；存在不同说话人、分支、用途或显示需求时，按出现位置或上下文建立独立翻译范围。

绑定信息声明回写粒度：引擎可以分别保存的字段使用独立译文；多个出现位置共用一个底层字段时，标明共享约束。场景专用译文能否落地由适配器能力决定，共享译文建议和实际可回写范围分别显示。

当前参考实现以 `context.syncGroup` 标记共享显示约束：同组字段保持相同译文，内部任务整组分发，
部分失败时整组保留原值。文字工作台中修改其中一项会同步组内显示字段；外部回包应完整返回同组条目。

游戏更新时，由映射过程继承唯一可确认的身份；有歧义的记录进入待确认。旧工具的序号 ID 通过带 manifest 指纹的映射表接入。包内身份与映射规则公开，第三方可以据此实现接力。

### 2. 完整语义与上下文

单元覆盖完整对话窗、自然段落、选择项或独立显示字段。场景内顺序、选择节点、互斥分支和邻接关系分别表达。跨窗阅读段可以组合展示，回写定位仍落到各自的原生单元。

工作包保留原文自然换行、段落、标点和空白。引擎要求的分页、窗口换行与排版换行另作结构化标记，译者可以区分语义分段和显示限制。

上下文标记来源，例如引擎提取、人工确认或模型推断。人物性别、说话人和分支条件可以为未知；推断摘要携带来源引用，与直接提取的原文分别呈现。任务包包含本轮必需的上下文闭包，外部 AI 可以从包内读到引用材料。

按场景与任务范围切批，完整单元作为最小分发单位。大场景通过保留邻接与分支引用的阅读段分批；每批附带适用术语、小样与必要前后文，控制重复输入成本。

任务范围与参考范围分别列出：本轮目标单元可填写，作为前后文附带的单元保持参考身份。术语和风格资料同样固定本轮版本，修改建议进入备注/问题记录；专门的术语任务另行声明填写入口。

### 3. 当前译文与接力版本

manifest 记录本轮源文快照和基础译文版本，baseline 保留本轮任务涉及的逐单元输入。初翻、校对、润色和补漏均从明确的当前版本导出。

回包对每条记录表达处理意图：提交译文、保留原值、待确认、主动清空。空译文与缺失记录分别处理；完整回包携带全部任务记录，增量回包由 manifest 显式声明范围和模式。系统读取意图与版本，处理结果与作者或模型自报的审阅状态分别记录。

源文快照、baseline 和绑定数据由导出器生成。AI 只处理指定填写字段，身份、指纹与技术映射由工具保留。文件摘要区分只读文件和可编辑文件；可编辑文件在导出时的摘要表示输入快照，回包允许其内容发生约定修改。

### 4. 合并规则

每条回包按基础值 B、工程当前值 C、回包值 R 比较。以下规则逐字段适用于译文和允许编辑的备注：

| 条件 | 接回动作 |
| --- | --- |
| R 与 C 相同 | 记录为相同成果，重复导入保持幂等 |
| R 与 B 相同 | 保留 C，本轮无文字改动 |
| C 与 B 相同 | 接受 R 及其明确的处理意图，形成新修订 |
| C、R 分别相对 B 修改且彼此不同 | 保留双方候选并生成冲突项，等待仲裁 |

表格按顺序判定；三者相同时保持原修订。明确清空等处理意图先解析为有效候选值，再参与比较，记录重复或冲突的处理意图供审阅。

比较前先检查源文身份、基础版本、任务范围、重复和未知 ID、字段类型与保护标记。重复 ID 单独报出，即使译文相同也保留重复记录的诊断。不同包的相同译文可合并，文件名、文件时间和导入顺序均不承担仲裁职责。

回包先进入暂存校验和差异预览。默认按一个任务包事务接回；部分接受作为明确操作，报告逐条列出已接受、未处理和冲突项。源文身份变化或导出基础版本无法核实时先完成重定位或变基，再接回文字；工程当前译文相对基础版本的正常变化由三方规则处理。

### 5. 显示规则与保护标记

人物动态引用、变量插值、数值格式、颜色标签、成对标签和引擎命令使用带类型与身份的标记。规则分别声明数量、配对、嵌套、可移动性、参数和结构位置；自然语言可调整的插值与固定位置的引擎命令分别校验。

阅读视图展示标记含义，例如“玩家姓名”；填写视图使用可校验的标记身份。原文中恰好长得像占位符的普通文字有独立的字面量/转义表示。多行正文、备注、引号、反斜杠和分隔符均需可往返的明确编码。

显示约束区分引擎硬性要求和参考建议。长度上限说明测量单位，像素限制附带字体/字号等测量条件；角色口吻或“建议简短”属于文字约定。结构校验、长度提示和语义审阅分别报告。

## 四 编辑模式

核心数据模型只有一套，编辑入口可以选择结构化 JSON 或纯文字填写表。manifest 声明本轮选用的编辑模式；同一任务范围有一个权威填写入口，reading 等内容为可重建的参考视图。

产品以版本化默认任务卡生成 `START_HERE.md`，自动填入当前阶段、填写入口、术语和上下文引用。普通用户导出即可交付，外部 Harness 或文字人员从任务卡开始处理。

纯文字模式继承现有 `TEXT` / `NOTE` 的低编码负担体验。新版本同时明确多行内容、字面量标记、空值及处理意图的表达；软件负责结构转换和字段核对，AI 直接完成文字工作。旧 `WORKBENCH-TEXT-v1` 按原语法读取，新增语法使用新版本号。

每个填写区提供该记录必要的原文、当前译文、说话人及上下文引用，减少在多个大文件间反复查找。参考视图中的原文与当前译文属于导出快照，返回时从唯一填写入口读取改动。

## 五 扩展与互通

核心定义文字、上下文、版本和任务接力。游戏绑定、图片区域、排版测量、术语增强等通过具名扩展接入。manifest 区分必需能力和可选能力；消费者遇到未知必需能力时报告具体不支持项，未知可选扩展按约定原样保留。

格式版本与产品版本独立演进。新增可选字段走兼容升级；更改单元身份、回包或标记解释时提供显式迁移。语言使用标准语言标签，例如 `ja`、`en`、`zh-Hans`、`zh-Hant`，术语与译文各自声明语言和适用范围。

公开交付包括规范、schema、中性样包、读写库、校验器和格式往返用例。第三方可以独立实现导出、编辑和导入；普通文字任务可以完整离线交换。

与既有本地化格式的转换应提供映射和保真报告。外部格式表达不了的场景关系、引擎绑定或修订信息，通过扩展/配套文件保留，并列入转换报告，便于用户选择适合的交付路径。

首个工具交换出口建议采用 XLIFF 2.1，公开游戏文本的映射配置。完整语义单元与显示片段分离，内联标记区分独立占位符和成对格式；上下文映射为标准备注、元数据和资源引用。第三方工具对扩展的实际保留情况纳入往返测试。[OASIS XLIFF 2.1](https://docs.oasis-open.org/xliff/xliff-core/v2.1/xliff-core-v2.1.html)

翻译记忆出口建议采用 TMX，积累已确认的原译对，保留来源与适用范围；场景顺序、版本接力和游戏绑定由原生工作包承载。[TMX 1.4b 原规范授权存档](https://www.ttt.org/oscarStandards/tmx/tmx14b.html)

语言标签规则采用 BCP 47，语言身份与软件显示名称分别保存。[IETF RFC 5646](https://www.rfc-editor.org/rfc/rfc5646.html)

## 六 参考实现验收

| 用例 | 验收结果 |
| --- | --- |
| 无改动导出、导入 | 文字、标记、关系和身份保持一致 |
| JSON / 纯文字双向转换 | 多行、空白、引号、分隔符、字面量标记及处理意图完整往返 |
| 同句不同说话人/用途 | 各自译文准确保留，明确共享的范围可复用建议 |
| 选择分支 | 保留互斥关系与场景顺序，阅读视图分别展示 |
| 三阶段接力 | 校对和润色从指定的当前译文继续 |
| 两人并行回包 | 不重叠的改动可合并，重叠改动按三方规则仲裁 |
| 重复导入 | 相同成果保持幂等，单包重复 ID 给出错误定位 |
| 旧回包接回新工程 | 源文和译文版本核对，失配与冲突有明确处理结果 |
| 动态姓名与成对标签 | 语义引用、配对及允许的重排规则得到验证 |
| 外部 Harness 接力 | 脱离产品 UI 阅读与处理，再接回同一项目 |
| 可选扩展往返 | 已知扩展正常显示，未知可选内容可保留 |
| 大包与损坏包 | 流式/分片读取可用；路径、成员数、展开大小、重复成员及摘要检查有明确诊断 |

中性样包覆盖上述情况，使用自造的普通游戏场景。格式验收核对数据与交换行为；游戏适配和文字质量分别沿用产品的验收流程。

## 七 与已有工具的衔接

旧工具 `rpgmaker-ai-work-v1`、`WORKBENCH-TEXT-v1` 及冻结 manifest 继续按原协议读取。参考实现通过转换器保留旧 ID、来源和有效当前译文，再建立产品级身份与修订。

现有纯文字接力已提供初翻、校对、润色任务卡及 TEXT/NOTE 填写入口；其导出报告记录当前译文指纹，导入按旧 manifest 与完整记录顺序核验。新契约进一步把本轮译文基线纳入机器合并，并增加并发冲突、语义上下文和可扩展标记规则。

0.2 工作包流程已实现 ZIP 交换、JSON/纯文字编辑、逐单元基线、三方合并与可选扩展保留，
具体字段和验证用例见 `packages/exchange` 的说明与 schema。XLIFF/TMX 互通、增强标记语义
和更广泛的外部工具往返继续按独立能力实现；旧工具包与产品格式分别保留版本标识。
