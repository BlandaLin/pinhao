# Agent 汉化产品交付验收

状态：2026-10-17 开工合同。定义完整公开版的交付结果；当前证据与待办见
[实现进度](IMPLEMENTATION.md)，每项按实际测试登记。

## 一 完成的定义

用户在一台没有开发环境的目标 Windows 机器上安装软件，配置自己的 API，选择认证范围内的游戏；软件完成制作、问题处理和验收，输出独立汉化版。关闭本产品并换一个目录，成品仍能启动和显示已制作的中文；源游戏与私人存档保持不变。

内部可以分模块开发与测试，最终交付按这条完整路径验收，不用提取演示、聊天页面或“模型说完成”代替。

首发平台为 Windows 10/11 x64；处理范围含受支持的32位老游戏。引擎目标为 MV、MZ、
VX Ace、VX、XP、2000/2003 与 WOLF；各版本按数据读写、完整组装和真实运行分别认证。

某引擎不存在回想房、气泡或某种辅助时标不适用并解释，不编造测试。探索阶段可以调整尚未承诺的能力等级；首发合同冻结后，必备能力测试失败就阻塞发布。只有用户明确批准变更发布合同，才能移除原有承诺，不能通过降低认证范围来绕过失败。

结构正确与语义正确分开。语义评估需要用户指定的文字校对流程与样本，技术开发不擅自润色剧情，也不能从无假名推导全剧情无漏译。

## 三 回归资产

中性 fixture 可以进入公开仓库，包含控制符、相同源句不同语境、长中文、选择分支、动态状态、图片小样、伪存档和损坏回包。使用自造文本，不附游戏剧情。

私有认证集合以本机索引保存游戏指纹、配方、测试位置与结果，不提交游戏本体、译文全文、私人存档或逆向厂商代码。按引擎、版本、发行方式和问题类型覆盖，不只挑一种干净样本。

API 集合至少包含两个不同供应商/端点配置，覆盖正常返回、断流、限流、工具参数错误、不完整文字回包及不返回用量。实际付费开发测试须获得用户对供应商、测试范围与次数的明确授权；这属于开发测试授权，与产品运行流程分开。

模型调用采用 BYOK 供应商直连。原始 usage 可作为可选诊断数据，供应商未提供时仍能运行与恢复。产品验收检查金额预算、单价表、费用估算、额度预留、积分和结算系统均不进入产品依赖或用户流程。

真实游戏视觉与操作验收需要授权窗口和可复现路径。无法到达的剧情不算已测；自动测试遇到焦点或权限问题要记录，不无限乱按键。

## 四 核心链路验证

以下验证随实现持续重现，稳定关键接口与实际交付链：

1. **执行与发行宿主。**打包后的桌面程序调用固定 Python，验证中文/长路径、工具崩溃、超时取消与恢复；进程树限制和生成代码沙箱按对应能力单独验收。固定协议与依赖布局已进入正式实现。
2. **完整成品链。**用一个 MV/MZ 与一个 VX Ace 代表样本，从只读原版经过工作台、数据构建、完整副本合成到启动/存读档。退出条件是 assemble 与验收契约成立，不是重复证明旧解析器能导出文本。
3. **真实模型接力。**使用内置任务卡在一段完整小场景上执行初翻、校对与可选润色，故意中断一次并制造一份坏回包。退出条件是版本、全局调度、执行结束条件、恢复和闸门可用，不以单次生成的文笔代替系统验收。

验证失败只修改相关架构决策与契约，不顺势扩大成新一轮全引擎或竞品研究。

## 五 实现顺序

| 顺序 | 工程交付 | 依赖与结束条件 |
| --- | --- | --- |
| 1 | 冻结产品规格、首发矩阵、核心交互与验收 | 用户已确认开工规则；细分版本认证随测试记录补齐 |
| 2 | 项目库、任务库、工具宿主、模型网关和版本契约 | 不依赖 GUI 的真实调用、恢复和错误测试通过 |
| 3 | RPG Maker 适配、文字接力、布局、assemble 与运行验收 | 认证样本完成端到端制作，不只导出 JSON |
| 4 | 桌面工作台贯通全部业务命令与状态 | 普通用户无需终端完成同一条流程 |
| 5 | 动态补漏、旧存档、辅助与其他承诺路线 | 逐能力完成，不用统一“支持”掩盖缺口 |
| 6 | 发行安装、干净机器回归、首次使用、隐私打包 | 全部首发硬性验收通过并发布准确能力表 |

界面可以先画线框和关键状态，避免等核心完成才发现交互不成立；实际界面与内核并行后仍调用同一套命令，不新增 UI 专用业务逻辑。

这是一款完整产品的实现分解，不是六次把目标缩小，也不把某一步的演示叫做最终公开版。

## 六 资源与质量测量

统一记录测试机器、游戏指纹、源文/当前译文版本、模型配置、任务卡、配方与工具版本、任务数量、重试、等待时间、人工介入和磁盘峰值。API 原始用量作为可选诊断项单列，不折算金额。对比自动流程与当前人工 Agent 工作流时使用同一任务，分别报告耗时、请求及返工情况。

界面准备一万与十万单元的中性项目，采用分页/虚拟化和后台处理，测量加载、检索与编辑响应。安装包、空闲内存、任务峰值和工具包空间在同一基准环境记录，再定公开指标。

质量问题分开计数：结构破坏、定位/漏译、术语/人称疑点、布局缺字、启动/存档故障。自动发现数量不是全部问题总数，未测范围单列。

## 七 变更规则

新需求要对应用户结果，并说明是否改变数据、适配器、权限、UI 和验收。无关功能进入候选，不直接混入当前实现；必要的完整流程修复不得借“控制范围”推迟。

技术栈只因有限验证中的实际不满足或用户关键约束而调整，不因某框架更流行而换栈。逆向只为明确适配阻塞服务，现有结论先查后用。

发布判断依据本表和已冻结支持矩阵，以实际成果和验收记录作为完成标准。
