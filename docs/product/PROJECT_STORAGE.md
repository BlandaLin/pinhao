# 工程与磁盘存储

新版采用游戏旁边的独立工程。软件可以解压到任意可写位置，游戏资源和制作进度不再默认进入系统 AppData。

## 默认位置

```text
E:/工具/拼好汉化/
  PinhaoWorkbench.exe
  data/
    catalog.sqlite             配置和项目索引
    electron-profile/          桌面程序自身的缓存与会话
    technical-recipes/          已注册的可复用配方及其代码

D:/游戏/
  旅店冒险/                    原版游戏
  旅店冒险-拼好工程/
    pinhao-project.json        工程身份与原版位置
    pinhao.sqlite              原文、译文、修订、任务与恢复状态
    workbench/                 提取定位与原生验证资料
    technical/                 适配脚本、必要工作资源与验证资料
    technical-lab/             本项目的候选、执行日志、依赖和验证记录
    requests/                  文字模型请求证据
  旅店冒险-汉化版/             独立成品
```

目录名称供用户辨认，工程内部仍用稳定 ID 区分同名项目。目录已存在时使用数字后缀创建新目录，不接管或覆盖已有文件夹。
工程目录不能建在原游戏里面。默认位置无法写入时，桌面端让用户选择另一个工程父目录，不静默改用系统盘。
程序自身的 `data` 无法写入时会报告错误；开发和验收可以通过 `PINHAO_DATA_DIR` 显式指定程序数据目录。

## 重新打开工程

在“游戏项目”选择“打开已有工程”，选取包含 `pinhao-project.json` 与 `pinhao.sqlite` 的工程文件夹，而不是原游戏文件夹。当前布局的工程可以重新登记到另一份便携程序的项目列表；原文、已接受译文、修订、任务候选和请求资料仍由原工程持有，不复制、不重新导入游戏。打开工程不会自动调用模型，进程中断时遗留的工作先暂停，用户继续制作后才执行。

此入口只接入位置未改变的当前布局工程。同一项目身份不能接入两个不同目录；旧布局、身份不符或数据库不可读会明确报错，原文件保留。完整工程搬家尚未支持：目录内的任务和原生定位仍可能引用原绝对路径，移动后请先放回原路径，不把仅修改目录记录当作恢复成功。

单个工程的数据库损坏不会阻止其他工程和设置打开。异常工程标明无法读取，不自动修复、清空或重建；原文件修复或磁盘重新接入后可以重试。程序级项目索引本身损坏仍会报错，不伪造一个空工作台。

成品默认生成在工程旁边，也可选择已有的输出父目录，软件会在其中新建成品文件夹。再次生成使用新目录；旧成品是否可清理由现有文件校验和存档保护决定，不能只按文件夹名字覆盖。若名称预留后被其他程序占用，该目录不会被移动到诊断区或清理。
分享 ZIP 只在用户导出时生成。

## 工程内的状态与资源记录

同一个 `pinhao.sqlite` 内，项目状态和进度保存在 `projects`，较大的资源清单与覆盖记录保存在 `project_resources`，不再随每次进度通知重写。读取工程时仍返回完整记录；同时接入资源成果与修改状态时使用同一事务，失败一起回滚。现有同布局工程首次打开时原子拆分这两项记录，不修改已接受译文、任务或请求文件，也不接管旧 AppData 工程。

技术任务的开始通知实时显示，但不单独生成整份恢复快照。完成的工具结果、完整模型对话、已计费请求记录及暂停、取消和结束状态仍按原机制保存。

## 按工具需要生成资源

内置工具直接查看原资源，多个技术任务共享只读输入。执行需要写入的工具时，只准备本次需要的安全工作文件，并复用已准备且基线一致的资源。
独立任务仍可并发，同一原生载体的修改继续经过联合校验与合并。
提取结果与原游戏可共同提供资源；文件工具标明来源，检查点核对实际来源和内容，不因只扫描某一目录而漏掉另一个来源。

这不是一套为全部文件预先分类的 AI 流程，也不根据扩展名猜哪些文件一定没有价值。
某些解包或重建工具需要完整资源包或较多关联文件，这些必要产物仍然占用空间。制作期间的峰值可能高于最终成品体积。
普通硬链接不是可写安全副本，不能把会修改原数据的共享链接当作原版保护。

技术 Agent 的受管本地脚本仍使用当前 Windows 用户权限；本布局不宣称提供操作系统级文件隔离，也不缩减已有技术工具能力。

## 请求证据保留一份有效内容

普通请求目录保存：

| 文件 | 内容 |
| --- | --- |
| `request.json` | 本次请求材料，密钥和凭证脱敏 |
| `events.jsonl` | 发送、响应、结束、解析和失败等事件元数据，不逐片段落盘，也不重复请求正文 |
| `final.txt` | 模型实际返回的正文，按原顺序保存；没有正文时不凭空生成 |
| `tool-calls.json` | 技术模型实际返回的工具调用，保留完整参数、调用 ID 与工具名，不在结果摘要中再复制 |
| `result.json` | 状态、时间、字数、用量、输出条目数及错误摘要，不再保存一份完整解析译文 |

调用被中断时，已收到的正文保留，并在结果中标明部分内容。只有推理没有正文的失败保留字数、时间、用量和错误，不默认保存整篇推理。
供应商没有返回的用量和费用不能当作零。

需要调查原始网络流时，在程序 `data` 目录放置 `diagnostics.on` 并重新启动。
该诊断模式才额外保存 `transport-N.txt`、`reasoning.txt` 和详细发送事件；诊断资料可能很大，且包含私有游戏文字。
关闭诊断只影响后续请求，不删除旧记录。正常模式也会随请求数量增加证据文件，并不承诺请求历史自动归零。

## 保留与清理边界

原版、存档、已接受译文、原始最终回包和必要恢复记录分别保留；不能为了清缓存让继续任务重新购买已经完成的翻译。
已被验证成果取代的临时小样和重建目录，可以按现有依赖检查清理。不能确认归属、包含存档或被用户修改的内容不按缓存删除。

本次采用新存储结构，不迁移或自动接管旧 AppData 工程，也不删除旧工程。
旧测试目录由用户另行决定何时清理。工程目录和请求证据属于私有工作材料，不应打入公开源码或默认分享包。
