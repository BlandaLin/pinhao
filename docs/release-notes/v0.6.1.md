# 拼好汉化 0.6.1 · 公开测试版 / Public Beta

## 中文

0.6.1 修正 0.6.0 的文字分批反馈、回复接收与恢复链。沿用短标记纯文字协议和现有技术 Agent、原生工具、并发及校对流程，不增加一套本地模型专用协议。

### 2026-11-04 修订

- 统一翻译、校对、补交、补查和连接测试的交稿说明，明确短标记、正文及完成标记的作用；修正块间空行、同行标记和附加信息的处理。
- 补交只列实际剩余目标及具体错误，保留必要语境与资料查询能力。个别条目反复失败时保留成果并列为待重试，其余任务继续；整批没有有效交稿或启用了严格暂停设置时仍暂停。
- 普通暂停续做不重复处理已经留待重试的问题项；明确重试时只处理剩余问题。未审完的校对文字保留当前译文、备注和既有记录，不提前标成校对完成。
- 替换重复试装请求的分批算法，逐批准备并立即派发，避免大容量规划长时间堵住后台；完整语义单元、必要语境及配置并发保持不变。

本次源码修订的联合回归 347/347、界面检查 92/92 通过；实际本机安装版使用隔离工程、本机模拟接口和内置原生工具验证了并发、暂停恢复、局部失败及成品逐位置回读。未新增付费模型或真实游戏游玩验收。

### 修复内容

- 分批不再按包含推理和固定开销的总输出用量持续缩小。保持完整语义单元、校对完整改文预留和发送前容量检查；真实截断只缩减已发送的受影响请求，保存的成果不重新请求，无法再拆分且无进展的单组停止重试。
- 接收与验收分离。先保存同次回复，再由同一终态解析器统一检查；前言作为协议外文字处理，不进入译文，也不提前丢弃后续正文、结束原因或已收到的用量。不按模型名称或前言关键词添加分支。
- 严格检查未知、只读、重复标记和竞争交稿，保留控制符、修订及关联组校验。明确闭合且通过检查的成果继续保存，截断或断流不会自动闭合尾块；没有明确完成标记，不认作全批校对完成。
- 修正附加信息中合法数组行与正文标记的冲突。术语、备注、疑点、补查、场景语境和 D2 原生小样门仍保留；提示中的可执行真实目标示例已删除。
- 未结回复恢复使用目标、源文哈希、修订、依赖、校对范围、连接、语言和提示等精准绑定。正文仍只有一份 `final.txt`，小型接收摘要不复制正文；脱敏或损坏的原稿不自动重放。成果或查询回执先持久化，再结束请求工件。
- 连续三次格式尝试无有效新增文字、明确审阅覆盖或真实新资料时，有有效成果的局部任务保存合格部分，剩余条目明确列为待重试；其他任务继续。整批没有有效交稿、严格暂停设置或全局阻塞仍暂停并排空已发请求。旧候选、文字增长或空分页不算新进展。进度与速度按正式接纳的文字计算。

已覆盖 SDK 到本机接口再到服务的接收、延迟正文、截断、断流、D2、并发排空与崩溃恢复。中性 worker 模拟游戏读写；这不等同于真实游戏原生回写或完整游玩验收。该轮实现与回归未调用真实或付费模型，也未验证客户本地模型的模板、上下文配置或翻译质量。

## English

0.6.1 fixes text batching feedback, response reception, and recovery in 0.6.0. It keeps the short-marked plain-text protocol and existing technical Agent, native tools, concurrency, and proofreading flow. It does not introduce a separate local-model protocol.

### November 4, 2026 Revision

- Unified delivery instructions across translation, proofreading, repair, evidence lookup and connection testing. Target markers, text and completion now have consistent meanings; block separators, inline markers and auxiliary information are handled consistently.
- Repair requests identify only remaining targets and their actual errors while keeping needed context and lookup access. A partially successful task can retain valid work and park its remaining problems for retry without stopping unrelated tasks. Entirely ineffective delivery and explicit strict-pause settings still pause work.
- Ordinary resume does not repurchase parked problems. Explicit retry handles remaining issues. Unreviewed text retains its current translation, notes and prior review record; it is not marked proofread.
- Replaced repeated full-request trial assembly with incremental planning and immediate batch dispatch. Large model capacities no longer require a long blocking planning window; complete semantic units, needed context and configured concurrency remain.

The source revision passed 347 joint regression checks and 92 UI checks. The actual local installation was verified using isolated projects, local simulated endpoints and bundled native tools for concurrency, pause/restart recovery, local failures and per-location product readback. No new paid-model or real-game playthrough acceptance run was performed.

### Download and Update

Choose an interface edition in the table above, extract the whole ZIP on Windows 10/11 x64, and run `PinhaoWorkbench.exe`. Pause tasks and close the old app before updating. Keep `data` beside the app and retain existing project folders at their original paths. Existing target-language choices are preserved; new settings default to English or Simplified Chinese according to the edition. Keep personal data, API settings, projects, games, translations, and saves out of shared application packages.

**Official builds are free. Do not pay to buy the official package. You supply the model API; its provider determines API charges.** The source ZIP is for development; `SHA256SUMS.txt` contains download checksums.

### Fixes

- Batches no longer shrink continuously based on total output usage that includes reasoning and fixed overhead. Complete semantic units, full-revision proofreading reserves, and pre-send capacity checks remain. Genuine truncation reduces only the affected sent request; saved results are not requested again. An indivisible group stops retrying if it cannot make progress.
- Reception is separate from admission. The app saves a reply before a single terminal parser checks it. Introductory text stays outside translations without discarding later text, the finish reason, or received usage. There are no model-name or introductory-keyword branches.
- Unknown, read-only, duplicate markers and competing deliveries remain strictly checked alongside controls, revisions, and linked groups. Explicitly closed, validated results survive interruptions. Truncation or disconnection does not close an unfinished trailing block; full-batch proofreading still requires explicit completion.
- Legal auxiliary array rows no longer collide with text markers. Terms, remarks, questions, evidence reading, scene context, and the D2 native sample gate remain. Executable examples using actual target markers have been removed from delivery instructions.
- Recovery binds unfinished replies to exact targets, source hashes, revisions, dependencies, review scope, connection, language, and prompt identity. There is still one `final.txt`; the small capture summary does not duplicate it. Redacted or damaged bodies are not replayed automatically. Results or evidence receipts are durable before request artifacts are finalized.
- After three consecutive format attempts without new valid text, explicit review coverage or genuinely new evidence, a partially successful task saves valid work and explicitly parks remaining targets for retry while independent tasks continue. Entirely ineffective delivery, strict-pause settings and global blockers still pause work and drain sent requests. Existing candidates, more prose or empty pages are not progress. Progress and throughput count formally accepted text.

### Verification Scope

The final implementation-stage joint check covered 22 test files: 297 passed, 0 failed, and 1 of 298 tests skipped due to an existing host symlink-permission restriction. That run included a private local-only regression. Desktop source build passed. The public response-chain regression tests use original neutral fixtures and local simulated endpoints, not customer replies or real game dialogue.

Coverage includes SDK-to-local-endpoint-to-service reception, delayed bodies, truncation, disconnection, D2, concurrent draining, and crash recovery. A neutral worker simulates game I/O; it does not establish real-game native writeback or complete play acceptance. That implementation and regression work made no real or paid model calls and did not validate a customer's local-model template, context configuration, or translation quality.

## 已知问题 / Known Issues

- 本版修复软件接收与验收链，不保证所有本地模型遵守交稿协议，也不保证译文语义正确。前言可被忽略不代表任意格式都会被接受；模型持续无有效交稿时仍会暂停。
- 未收到用量时费用仍未知。取消本机接收不证明服务商停止生成或停止计费，不承诺统一的速度、费用节省比例或缓存命中。
- 引擎、自定义插件、加密资源、动态文字、图片和字体布局的既有边界仍适用，详见 [0.6.0 已知问题](v0.6.0.md#known-issues)。数据检查和手机预检不替代真实游戏与设备验收。

- These fixes cover the app's reception and admission chain. They do not guarantee that every local model follows the delivery protocol or produces accurate translations. Ignoring introductory text does not authorize arbitrary output formats; persistent failure to deliver still pauses work.
- Missing usage remains unknown, not zero. Cancelling local reception does not establish that a provider stops generation or billing. No fixed speedup, cost reduction, or cache-hit rate is promised.
- Existing limits for engines, custom plugins, encryption, dynamic text, images, and font layout remain; see [0.6.0 known issues](v0.6.0.md#known-issues). Data checks and mobile preflight do not replace real-game or device acceptance.

Keep the original game and saves. Check dialogue, choices, branches, fonts, and save/load in the finished copy. Report the version, interface edition, steps, and error in [Issues](https://github.com/BlandaLin/pinhao/issues/new/choose); redact keys and personal information. Do not publicly upload complete games, private projects, API settings, or saves.
