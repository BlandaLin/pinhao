# 汉化工程经验

## 完整文本与回包

提取粒度以对话窗、段落、选择项和显示字段为单位，不按字符硬切。
保留人物、邻接台词、场景位置、条件和术语；技术标识与显示文字分开。
既有中文要作为可追踪的当前基线，补丁只改允许字段，不让后来的同 ID 静默胜出。
对重复源串可以共享默认译文，但应允许不同语境的单位覆盖。

先验证原样回写逐字节一致，再交小样确认文字与布局。回包按稳定 ID 合并，
不按行数或文件排序拼装；未完成条目和语义疑点单列，不偷偷补写猜测译文。
初翻、校对、润色可以串行接力，但每一阶段都应保留进入时的明确版本与差异。

## 容易漏掉的文字

数据库和事件之外还要查插件参数、脚本显示字面量、外部文本、动态状态、
卡牌名称、菜单、回想入口、图片文字和默认存档字段。查无假名不等于没有漏翻，
已有中文和繁体字段也需要清点；不要靠无差别全字符串替换改动路径、代码和逻辑 ID。

补漏要形成“来源 -> 单位 -> 文字任务 -> 回写 -> 回归样本”的闭环。
出现新类型问题时，优先扩大同类搜查，再把实例沉淀成通用检查或适配配方。
程序预警用于排序与复核，不把长度比、符号计数或自动语义评分当最终语义判断。

## 字体与排版

中文字形覆盖、字体风格、实际像素宽度、行高和窗口预算分别验收。
绘制和测量应使用同一套译文与字体规则。重点测试姓名框、长选项、卡牌说明、
动态状态、字号控制符与气泡窗口，不能只通过缩字号或按原文字数补空格解决。
字体附带原许可证；不同游戏保留其视觉风格，不把统一换楷体当作通用答案。

## 旧存档

旧存档可能固化原文默认人名、动态说明和缓存。兼容补丁优先在加载或显示时
迁移明确已知的原版默认值，保留玩家自定义名字，不改玩法变量和剧情开关。
检查回想房、回想台词、物品描述与新存档的差异；历史存档只读备份后再做副本测试。

## 成品与分享

数据 build 只是重建的数据集合，不自动等于完整可玩游戏。
在新副本合成后测试启动、标题、选项、对话/选择分支、保存读档、回想、菜单与字体，
说明实际测试范围，不能凭某个玩家表示可用就宣布全部剧情无误。
分享包排除个人存档、翻译工具状态、授权与密钥、机器日志、调试文件和内部报告。
免费声明与必要使用说明保留，发帖草稿不属于成品。大包需要分卷时提供明确合并方式。
